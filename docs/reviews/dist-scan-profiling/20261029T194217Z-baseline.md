# Distribution scan profiling baseline — 2026-10-29

The diagnostic records repeated filter glob calls and separates their aggregate
pass duration from include expansion. In this local checkout, the filter passes
accounted for nearly all measured validation time. This is a measurement baseline;
no traversal, matching, caching, dependency, CI configuration or outside-symlink
policy changed, and no optimization was tested.

Capability: **Level 4 Validated** in this implementation branch, available only
when explicitly compiled with `dist-profile`. Performance evidence:
**Empirically informed**, from one local host and two filesystem shapes.
Independent review, CI and Gate 2 remain separate requirements.

## Counter contract

Each diagnostic invokes the existing validator body exactly once with a fresh,
invocation-local counter context. Counters and clocks compile out without the
feature. Repeated/concurrent calls and failed validation are tested.

- `read_dir_calls`: attempted `fs::read_dir` calls inside
  `collect_regular_files` only. It excludes directory reads internal to `glob`.
- `expand_glob_calls`: direct `glob::glob` calls for non-prefix includes.
- `glob_matches_calls`: `glob::glob` calls from exclude/forbidden matching.
- `expand_includes_elapsed_ns`: include expansion, including its sorting.
- `filter_elapsed_ns`: sum of exclusion and forbidden passes; the intermediate
  sort/deduplication is outside this measurement.
- `total_elapsed_ns`: full validation, including parsing/version reads and
  instrumentation overhead. Failures retain partial counters and errors.

These are API-call counts, not matched-file counts or a total filesystem-syscall
count. They do not establish the earlier ad hoc “577k directory reads” figure.

## Fixture integrity and current matching behavior

The committed YAML parameters generate 500 tracked regular files across four
nested directory levels and five buckets, plus tracked VERSION and note files.
After committing only that baseline, the generator adds three untracked files
(two nested), two hidden files (one in a hidden directory), and one symlink to
an existing in-root file. It then adds the untracked manifest. Assertions check
502 tracked paths, seven genuinely untracked paths, 505 regular files beneath
`tree/`, one symlink, and the exact selected set of 507 paths before/after
validation as appropriate. Git metadata uses fixed commit dates and an empty
template; no generated tree is committed.

A pre-implementation characterization attempt found that
`**/__pycache__/**` alone did not exclude the fixture's nested cache.pyc file.
The final fixture mirrors both patterns from the real manifest, including
`**/*.pyc`, which supplies that exclusion. Untracked non-cache files, nested
untracked files, both hidden files and the in-root symlink remain explicit
positive membership assertions. The observed matcher behavior was preserved.

## Rerun procedure

Prerequisites: Rust/Cargo, Git and a Unix filesystem supporting symlinks. Run
from the repository root. Use the explicit feature build and binary, because the
normal released/default build does not register this manual diagnostic:

```sh
cargo build --release --manifest-path tooling/rust/Cargo.toml -p agov --features dist-profile
AGOV_TOKEN_ROI=0 tooling/rust/target/release/agov dist diagnose --json
# Optional manifest; omit --json for the human-readable summary.
AGOV_TOKEN_ROI=0 tooling/rust/target/release/agov dist diagnose --manifest agf/dist/release-manifest.yaml
```

Generate, verify and measure the same temporary fixture with three independent
subprocess samples; the test removes the fixture afterward:

```sh
cargo test --release --manifest-path tooling/rust/Cargo.toml -p agov \
  --features dist-profile --test dist_scan_profile \
  record_fixture_baseline -- --ignored --exact --nocapture
```

For the real tree, repeat the JSON invocation three times without changing the
checkout. Save output outside that checkout. Record source SHA, feature/build
configuration, ignored-file footprint and cache conditions before interpreting
numbers. ROI logging is disabled for measurement. This diagnostic is not wired
into a CI job or governance gate. Restore the normal binary explicitly with
`cargo build --release --manifest-path tooling/rust/Cargo.toml -p agov` afterward
when that is the intended local operator configuration.

Enable profiling through the `agov` package feature, which forwards it to core.
Cargo dependency-feature unification is additive: enabling only
`agov-core/dist-profile` does not activate the CLI's separate feature. Such a
mixed configuration can expose vocabulary entries without the command and fail
the unchanged bidirectional audit; it is not the supported profiling build.
Workspace `--all-features` compatibility was tested successfully. Its existing
MCP transport harness rebuilds a default CLI; the explicit profiling command
above was rerun before collecting these samples. No MCP tool was added.
