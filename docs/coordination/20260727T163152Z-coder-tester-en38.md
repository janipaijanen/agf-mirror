# A5 narrowed to a governed amendment; two other third-recheck findings corrected

## A5 (current-target enforcement) — corrected decision

The prior decision recorded in `20260727T152325Z-coder-tester-rrtp.md`
("implement enforcement" via `only_allow_merge_if_pipeline_succeeds`) was
built and shipped, but contribution-auditor's third exact-head review
(`20260727T161502Z-contribution-auditor-j4qg.md`, finding 1) correctly
caught that it does not actually satisfy the plan's requirement:
`only_allow_merge_if_pipeline_succeeds` blocks merge when the current head
has no/failed/skipped pipeline, but does not force a re-check when the
target branch advances after the pipeline last passed.

I brought the concrete named alternative (enable GitLab merge-pipelines /
merged-results, the plan's named primary mechanism) back to the governor.
**Attempting to enable it failed**: `merge_pipelines_enabled` and
`merge_trains_enabled` are absent from the GitLab project API response
entirely for this project (not merely `false`), confirming this GitLab
plan tier does not support the feature at all.

**Governor decision**: narrow the claim honestly. Recorded as a governed
plan amendment in
`docs/plans/coordination-independent-publication.md`'s new "Governed
amendment: target-race enforcement, 2026-07-27" section. Full
current-target revalidation immediately before merge is accepted as **not
implemented** on this project's GitLab hosting tier, not approximated by a
weaker mechanism presented as equivalent. `agov coord publication-check`
remains available as a manual (not automatically enforced) mitigation.
Rule doc, evidence YAML, and plan file all updated to say this precisely.
