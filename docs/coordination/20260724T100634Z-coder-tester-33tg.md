# Issue #30 diagnosis and Gate 1 routing

Issue #30 is reproducible, but the observed rejection is consistent with the
current authority model rather than a schema contradiction.

The Gate 1 schema intentionally accepts a non-empty role string. Semantic
validation then reads `agf/agents/MANIFEST.yaml` and permits the two mandatory
advisors plus roles whose manifest status is `active`. `build-engineer` is a
known role with status `suspended`, so it must not be accepted as an available
advisor unless the governor changes its authoritative status.

The actionable defect is diagnostic precision: the validator currently
reports every disallowed role as `unknown advisory role`, conflating a typo or
nonexistent role with a known but inactive/suspended role. That message makes
the valid rejection look like schema/manifest drift and obscures the remedy.

Recommended narrow change after Gate 1 approval:

- preserve the current required-advisor and active-role semantics;
- retain manifest entries and statuses while loading the allowlist;
- report genuinely absent roles as unknown;
- report known non-active roles with their authoritative status, for example
  `advisory role is not active: build-engineer (status: suspended)`;
- add unit/integration fixtures for active, suspended, skipped, and unknown
  roles, plus manifest-unavailable fallback behavior;
- document that the schema defines shape while the manifest-backed semantic
  validator defines currently available advisory roles.

This is non-release maintenance. No implementation has started because the
repository requires Gate 1 approval for this non-trivial validator-contract
change.
