# Review: review-depth metadata as a career signal

The governor-reviewer relayed a fourth external Lumo response identifying a
realistic abuse case that still slipped through the previous minimum schema:
categorical `review_depth` on every named human decision record.

Accepted from the response:

- Even categorical review-depth values become sensitive when they are present
  on every permanent, grep-able decision record.
- A manager does not need AGF analytics to misuse this data; basic text search
  can rank humans by how often their records say `skimmed` versus
  `substantively-reviewed`.
- The signal is more dangerous than raw decision counts because it maps
  directly to performance language such as "thorough" or "rubber-stamping."
- Review depth should therefore be incident-gated by default: record it when
  reconstructing a failure, disputed gate, or exception, not during every
  routine approval.

Critical assessment:

- This is a strong correction to the prior proposal. "Categorical only" is not
  enough if the category is dense, permanent, and attached to named humans.
- The trade-off is real: incident-gated review depth makes it harder to detect
  shallow review patterns proactively. That is acceptable because proactive
  detection requires the same dataset that enables surveillance.
- Routine decision counts still leak workload distribution, but that is a much
  coarser and less quality-coded signal than review depth.

Change made:

- Revised the proposal to remove routine `review_status` from the `principal`
  examples.
- Added language that review depth should be incident-gated by default and
  tied to a specific reconstruction context.
- Added a tooling non-goal: AGF should not aggregate review depth by person.

Recommendation:

If this becomes a Gate 1 plan, require any review-depth schema work to prove
that the field is not mandatory on routine decision records and that AGF does
not provide person-level review-depth aggregation.
