# Review: minimum viable principal metadata

The governor-reviewer relayed a third external Lumo response on the minimum
schema shape that preserves the anti-surveillance boundary without making
small-team AGF adoption bureaucratic.

Accepted from the response:

- Use a two-tier model: Tier 0 is current role-first coordination with no
  principal block; Tier 1 adds optional principal metadata only when delegated
  authority must be recorded.
- Do not require principal metadata for solo or small-team use.
- If a principal block exists, keep the minimum focused on identity, principal
  kind, positive delegation scope, optional expiry, optional voluntariness, and
  non-delegable approval boundaries.
- Keep review depth categorical and attach it to human review or decision
  records, not every AI-authored handoff.
- Represent contestation as an additional immutable coordination record that
  references the disputed delegation.

Critical corrections:

- Lumo's example used a different schema vocabulary (`sender`, `role`,
  `references`, and new message kinds such as `disavowal-record`). AGF's
  current coordination schema uses `from`, `to`, `references-to`, and the nine
  defined message kinds. The proposal now translates the design idea into AGF
  vocabulary instead of copying the example literally.
- A global "principal role" or new message kind should not be assumed in this
  exploratory proposal. That belongs in a Gate 1 implementation plan if the
  feature advances.
- "No principal means nothing to aggregate" is directionally useful but not
  strictly true: git authors, role names, and timestamps can still be analyzed.
  The stronger claim is that AGF should not add extra personal principal
  identifiers unless delegation actually needs them.

Change made:

- Added a `Minimum viable shape` section to the proposal.
- Documented Tier 0 and Tier 1, the minimum Tier 1 `principal` block, and an
  AGF-shaped contestation example.
- Clarified that the contestation example names a future design direction and
  is not yet accepted by the current coordination schema.

Recommendation:

If planner-architect turns this into a Gate 1 plan, keep the first
implementation narrow: optional `principal` metadata plus contestation
visibility. Defer new message kinds, principal analytics, dashboards, and
global identity defaults.
