## Exact evidence

GitLab's REST representation hides the creation error: each pipeline reports
`yaml_errors: null`, zero jobs, and no start time. GitLab GraphQL exposes the
pipeline-level diagnostic through `Pipeline.errorMessages`. All three pipeline
IIDs (`7175`, `7176`, and `7177`) report the same message:

> `'release:assets-verify-preview' job needs 'agf:dist:preview' job, but
> 'agf:dist:preview' does not exist in the pipeline. This might be because of
> the only, except, or rules keywords. To need a job that sometimes does not
> exist in the pipeline, use needs:optional.`

GraphQL also reports `failureReason: "The pipeline failed due to an error on
the CI/CD configuration file."`, `totalJobs: 0`, and `yamlErrors: false` for
each pipeline. This corrects `qqdj`'s inference that default-branch lint had
excluded a pipeline-wide configuration error. The lint result proved the
static/default-branch graph, not this merge-request rules evaluation.

The exact source configuration explains the message:

- `release:assets-verify-preview` is included for every
  `tooling/rust/**/*` merge-request change and has a mandatory artifact need
  on `agf:dist:preview`.
- `agf:dist:preview` is not included for a
  `tooling/rust/Containerfile.agov`-only change; its rule names `agf/**/*`,
  `.gitlab-ci.yml`, two review documents, and
  `tooling/rust/scripts/check-release-self-sufficiency.sh`.
- The changed path was exactly `tooling/rust/Containerfile.agov`.

The OCI self-test and scan rules did match relevant paths, but GitLab rejected
the whole dependency graph before materializing any job. This was therefore
not an OCI path-trigger miss, quota exhaustion, or a runner failure.

for CI cost and the intended release-asset proof. Do not patch by guess.

## Advisory follow-up

The diagnostic workflow should record GraphQL `failureReason` and
`errorMessages` whenever REST reports a zero-job failed pipeline with no YAML
error. That would have reduced this investigation from an ambiguous trigger
failure to a deterministic dependency-graph diagnosis. Route this as a future
learning/control only after the release blocker is stable.
