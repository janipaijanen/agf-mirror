## S2-G1-F1 — representation conflicts with immutable records

Check status: reviewed
Outcome: fail
Requirement strength: mandatory
Impact: critical
Enforcement: blocking
Basis: issue #122, the append-only coordination-publication rule, and prior
independent refinement `hqps`.
Finding state: open
Risk disposition: none

The algorithm checks an earlier pending record's own `superseded_by` field.
That record is immutable and cannot acquire the field after a later correction
exists. The plan says a later record may instead carry `supersedes`, but none
of its reader algorithms or tests derives the reverse edge from that field.
This misses the motivating `th6m`/`mhq1` case and contradicts the already
recorded issue refinement: later record only, `supersedes: [id, ...]`, with
`superseded-by` derived by readers.

Resolution condition: use a one-way `supersedes` array on the later record,
derive reverse annotations/filtering from it, remove the literal
`superseded_by` requirement from old records, and rewrite the tests around
the real append-only publication sequence. If the approved parent work
order's “field pair matching qbka” clause must change, obtain a governor
amendment rather than claiming the deliberately asymmetric shape matches it.

## S2-G1-F2 — an untrusted edge can silently hide another role's obligation

Check status: reviewed
Outcome: fail
Requirement strength: mandatory
Impact: critical
Enforcement: blocking
Basis: the plan and rule both constrain supersession to the same audience;
`hqps` requires target existence, temporal order, and cycle validation.
Finding state: open
Risk disposition: none

The plan drops an obligation whenever the named target merely exists. It does
not validate that the target precedes the superseder, reject self-edges or
cycles, check compatible sender/decision authority, or enforce the stated
same-audience boundary. Any mistaken or hostile record could therefore hide
another role's live obligation from the default queue. “A reviewer may catch
it later” is not a sufficient control after the tool has already hidden it.

Resolution condition: define and test existence, strict temporal/order,
self-edge/cycle, same-audience, and sender/authority rules before an edge may
affect the live queue. Invalid or unauthorized edges must fail safe by leaving
the predecessor visible with a diagnostic. Provide an explicit history/debug
view for valid filtered records.
