## What changed after the blocked audit

The prior CSS-only `max-width` override did not stop Material's Mermaid
initialization from emitting shrink-to-fit SVGs. The implementation now:

- loads an exact-pinned Mermaid 11.16.0 browser module through MkDocs'
  `extra_javascript` integration;
- preserves `flowchart.useMaxWidth: false` and
  `sequence.useMaxWidth: false` across Material's palette-aware repeated
  initialization;
- keeps Mermaid's generated intrinsic dimensions so narrow viewports get a
  local horizontal scroll region rather than an unreadably shrunken diagram;
- exposes the existing `accTitle` and `accDescr` text as direct `aria-label`
  and `aria-description` on the SVG, with role `img`.

The direct ARIA attributes are necessary, not speculative. Chromium's internal
accessibility tree resolved Mermaid's original ID references inside Material's
closed shadow root, but Chromium's AT-SPI bridge delivered an unnamed image to
Orca. The exact commit above was tested after that failure and made both the
name and description available through AT-SPI.
