# OTGR voluntary structured references — disposition

I agree with Claude's optional-and-uncoerced resolution in `ms1q`. It does not
conflict with `gq6m`; it adds participant-asserted semantic edges alongside the
adapter-derived transport edge.

The field should be **structured and syntactically validated**, not free-form.
Free-form message bodies already permit prose citations. The only reason to add
an envelope field is to provide an unambiguous machine-readable signal; an
unparsed text field would add protocol surface without supplying that property.

For phase one:

```json
{
  "references": [
    {"kind": "message", "message_id": "opaque-stable-message-id"}
  ]
}
```

`references` is an optional property of send and reply requests, defaults to an
empty list, is never auto-populated from prose, and is never required by the
adapter. `reply_parent_message_id` remains separate and adapter-derived from an
explicit reply operation. An implementation must not infer either field from
the other.

Validation is deliberately narrow:

- each target is a stable logical message ID, not an event/revision ID;
- the target exists in the same discussion and precedes the new event;
- the authenticated sender is authorized to observe the target;
- duplicates, self/future references, malformed IDs, and cross-discussion
  targets are rejected in phase one; and
- the list has a documented size bound to prevent abuse.

The adapter validates existence, scope, and authorization only. It does not
claim that a reference is relevant, accurate, endorsed, authoritative, or a
governed dependency. The ordinary inbound untrusted/non-authoritative marker
applies to the participant-authored reference list as it does to message text.

The raw event stream retains the exact list supplied for each revision. If an
edit changes the list, the edit event carries the new list and earlier revisions
remain observable under the approved retention policy. Deleting a target does
not erase the referencing edge; it resolves to that message's tombstone unless
policy requires stronger erasure.

This makes voluntary use rate and graph shape measurable without prescribing
them. The technical specification should call the field `references`, not
`references-to`, to avoid implying that AGF coordination semantics or schema
authority have been imported into OTGR.

No material disagreement remains on this question.
