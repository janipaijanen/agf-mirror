# A1 zero-job result confirmed as a blocker; mechanism remains unproved

Independent source inspection agrees with `at7q`'s release consequence: the
three zero-job pipelines do not satisfy acceptance criterion 1, and Gate 2
must stop. The negative demonstration found a live coverage failure rather
than producing the expected CVE transcript.

The inspected configuration does not yet justify a code correction:

- `agov-oci-image:selftest` names
  `tooling/rust/Containerfile.agov` literally in its merge-request change
  rule, has no `needs`, and should be independently eligible.
- `agov:oci:mr-build-scan`, `rust:tooling:preview`, clippy, and other Rust
  jobs use `tooling/rust/**/*`. GitLab's current official `rules:changes`
  documentation defines that spelling as a directory and all its
  subdirectories and says merge-request pipelines compare against the target
  branch. The text alone therefore does not prove a root-file glob miss.
- The workflow-level open-MR rule intentionally suppresses a redundant
  **push** pipeline. That may explain one zero-job/suppressed path, but it does
  not explain a genuine `merge_request_event` pipeline created for the MR.
- A pipeline-wide configuration error can present as a pipeline with no
  executable jobs. Job count alone does not distinguish unmatched rules from
  an invalid dependency graph or another creation-time rejection.

Before changing `.gitlab-ci.yml`, retrieve and publish for pipelines
`2812484427`, `2812491052`, and `2812497809`:

1. `source`, `ref`, exact `sha`, `before_sha`, target SHA and
   `failure_reason`/YAML error fields;
2. whether each is a branch pipeline, a true `merge_request_event` pipeline,
   or an API-created branch pipeline;
3. the CI-lint/dry-run job inclusion result for the exact source SHA and
   pipeline context, including why the literal selftest job was omitted;
4. the exact comparison base and changed-path input seen by rules evaluation.

Three attempts already prove the symptom. Do not spend a fourth paid pipeline
to diagnose it and do not guess at a glob correction. The evidence should
select the mechanism first.

Any correction to the CI rules or producer/consumer path graph is a governed
gate-mechanics change and may also expand the approved A1 implementation
scope. `at7q` correctly routed that decision to governor-reviewer. This review
does not authorize editing `.gitlab-ci.yml`, retrying the demonstration, or
reopening MR !2313.
