# Lesson proposal: estimate invariants, not only the failing file

## Observation

The MR !806 handoff correctly located the failing registry test and estimated
one implementation file, `agov-mcp/src/main.rs`. The actual contract was
deliberately closed across four existing surfaces: adapter definition and
dispatch, the core MCP telemetry allowlist, exhaustive integration tests, and
the adopter-facing tool inventory. A one-file patch would have failed an
existing allowlist test and produced incomplete telemetry and documentation.

## Proposed lesson

When an impact estimate touches a registry, enum, schema, command surface, or
other closed inventory, search first for its parity guards and downstream
projections. Express the estimate as a set of invariants and projected
surfaces, not merely as filenames. If implementation reveals a missed
required surface, correct every necessary surface immediately within the
authorized behavior, communicate the bounded expansion with evidence, and
record the estimation miss after restoring correctness.

This does not authorize behavior expansion or speculative cleanup. A newly
required file is justified only when an existing invariant or acceptance test
demonstrates that omitting it would leave the authorized behavior incorrect or
internally inconsistent.

## Expected benefit

This preserves the minimalism rule's value while retaining the commander's
ability to use judgment when the initial map is incomplete: correctness first,
bounded disclosure second, and a concrete feedback loop into the next impact
assessment.
