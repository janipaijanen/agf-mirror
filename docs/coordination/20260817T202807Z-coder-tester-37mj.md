## What the evidence does and does not establish

The DD observation is directionally credible. A fresh `agov coord status`
still prints a long pending-handoff list, `agov coord pending` still exposes
old unresolved required acknowledgements, and the Rust validator already
contains the `agov.validate.assistant_drift` primitive. A cold-starting
operator therefore faces genuine signal-to-noise cost.

The raw counts are not yet a workload baseline, however:

- `agov coord status` currently reports obviously completed or superseded
  work as pending, including the reactivation/staffing re-review and the
  v2.6.1 round-3 review. “81 pending handoffs” is therefore a projection-
  closure quality signal, not evidence that 81 live tasks need execution.
- “547 branches” mixes active, merged, historical coordination, review,
  plan, protected, and possibly audit-preserving branches. Without age and
  disposition buckets, the count does not demonstrate that a fixed branch
  lifetime would be safe or useful.
- The 51 rule-copy findings are produced by an existing validator whose
  intended remedy is to replace copied AGF trees with loader references or
  move intentional overrides. They should be classified by canonical tree,
  expected override, and actionable drift before selecting a recurrence
  cadence.

The DD appropriately says these counts do not prove improper work. The
project response should preserve that qualification.

## Proposed response shape after those corrections

### Phase 0 — definitions and baseline, no new enforcement

Define one computed inventory with mutually exclusive states and age buckets:

- obligation: live, human-gated, completed-but-unacknowledged, superseded,
  stale-projection, or historical;
- branch: active-MR, closed/merged-MR, protected, evidence-preserving,
  orphaned, or explicitly retained;
- drift: actionable difference, expected project override, bootstrap-only,
  or false positive.

Record counts, oldest age, arrivals, dispositions, and unresolved exceptions
for at least two comparable snapshots. This is the minimum evidence needed
to set a useful threshold.

### Phase 1 — triage objectives, not closure SLOs

Prefer an **attention/triage objective**: a new live obligation should be
classified, owned, and either acknowledged or escalated within a stated
window. Do not promise closure within that window; many records legitimately
wait on a human gate, an external dependency, or preserved historical state.
Measure the clock only while the obligation is actionable by its owner and
pause it with an explicit reason when human-gated.

For branches, use an age-based **review trigger**, not a maximum lifetime:
flag a branch only after checking MR linkage, last activity, merge state,
protected status, unique unpublished content, and evidence-retention need.
Deletion remains an explicit governor decision.

For drift, run the existing assistant-drift validator at a defined checkpoint
(release readiness is the strongest low-noise candidate) and route only
actionable classifications. Do not create a calendar job before showing that
release-bound checking is insufficient.

### Phase 2 — computed queue-health report

Prefer a deterministic `agov` report over manually maintained dashboard
content. A periodic coordination snapshot can preserve evidence, but it must
be generated from the report and must not become the authoritative queue.
The smallest useful output is age buckets plus state, owner, blocker, and
source link; trend storage can wait until two snapshots demonstrate value.

Proposed ownership remains subject to governor approval: planner-architect
classifies planning obligations, coder-tester verifies technical/MR state,
build-engineer owns any CI/report integration, and governor-reviewer decides
exceptions, destructive branch actions, and policy thresholds. No role should
be made responsible for closing work it lacks authority to close.

## Success criteria for a future Gate 1 plan

A later plan should state observable outcomes rather than a raw-count target:

1. Every reported pending item has a current state, owner, source, and blocker.
2. Completed/superseded records no longer appear as live work, while remaining
   available in the audit trail.
3. Age and arrival/disposition rates are reproducible from repository/GitLab
   data at an exact revision.
4. No branch is deleted and no MR is closed automatically.
5. The mechanism demonstrably removes more recurring review effort than it
   adds; otherwise park it under the simplicity rule.

enforcement and tooling split into later Gate 1 decisions only if the baseline
