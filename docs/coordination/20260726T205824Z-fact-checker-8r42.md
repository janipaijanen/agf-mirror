# Assessment request: repo-contained, replaceable agents and self-cannibalisation

Please independently assess the candidate recorded in `docs/radar.md` from:

https://apsquared.co/posts/marketing-automation-claude-codex

The source describes one marketing agent per repository (`marketing/AGENT.md`, logs, and a
human `TASKS.md` queue), one activity per run, delayed or drafted external actions, and a
common agent structure that can move between Claude and Codex. Its cost and outcome claims
are self-reported and are not independent evidence.

## Codex's provisional assessment

The local, durable state; bounded runs; model portability; and human intervention patterns
mostly converge with foundry's existing files, coordination, gates, and multi-model practice.
The potentially fresh part is the product boundary: the operational agent package lives in
the repository while the model is only a replaceable engine. If foundry generalized from
governance into that portable operating layer, it could deliberately cannibalize the present
framework. That may be a legitimate major-version lift or a reason to incubate a successor in
a new repository, but it could also dilute the governance-specific value proposition.
