# Run-list addition: issue #128 (cadence register) under the post-v2.9.0 window

Governor-requested. When `mmm3`'s canonical run-list is next refreshed (or
its successor is written), add one line under the post-v2.9.0
capability-developer / Propeller window:

> **#128 cadence register** — Propeller friction-mining candidate /
> capability-developer input; Gate 1 plan on promotion.

## Why it belongs there, not as a pre-authored plan now

Issue #128 (*"Consolidated cadence register / 'year-clock' for recurring
governance obligations"*) is filed and its body already defers it to this
window and notes it "needs its own Gate 1 plan." Writing that plan before the
window would lock a design (which obligations, plain-file vs docs-site
rendering, adopter template) that capability-developer's one-shot review and
Propeller's first friction-mining pass are meant to inform. It is a textbook
Propeller lane-2 target — "documentation that causes agents or humans to make
the same mistake repeatedly" (missing an audit because nothing tracks its due
date). If Propeller surfaces it as a *material* candidate, it earns its Gate 1
plan then; if not, nothing is lost.

The only gap today is that #128 is an orphan issue with no line on the
canonical run-list, so a cold-starting session in the window would not see it.
This note closes that gap; the run-list owner folds it in.
