# Corrected deliberation guide: Irssi client and review dispositions

The governor rejected WeeChat as the client. Although WeeChat and Tencent
WeChat are unrelated projects, defending a confusing name has no operational
value here. The guide now uses Irssi, a long-established terminal IRC client.
The Ergo server and Tailscale transport recommendation are unchanged.

## Review disposition

This revision accepts all three findings in `kjqm`:

- **DG-1 accepted:** the protocol now distinguishes review acts from
  co-authoring acts. Participants must name the intended author, recorder and
  reviewer; co-drafting contaminates a later review, which must be declared
  non-independent and may require a third reviewer at governor discretion.
- **DG-2 accepted:** acceptance now includes a deliberately wrong certificate
  pin that must fail before SASL. The guide generates a one-year certificate,
  installs a weekly 30-day expiry check, and gives a backup, authenticated
  distribution, replacement, re-pin and positive/negative retest procedure.
- **DG-3 accepted:** denial from a non-client-tagged tailnet node is mandatory.
  The deployment cannot be accepted if the negative access-control test cannot
  be performed.

## Irssi-specific security tradeoff

The corrected guide combines a locally transferred trust anchor with an
out-of-band SHA-256 certificate pin and leaves TLS verification enabled. Irssi
does not provide WeeChat's encrypted secure-data store: its SASL password is
saved in plaintext in `~/.irssi/config`. The guide discloses that fact,
requires mode `0600` plus encrypted or equivalently protected dedicated-VM
storage, and directs operators to stop and design SASL EXTERNAL client-certificate
authentication if that exposure is outside the threat model. It expressly
forbids improvised shell or command-line password injection.
