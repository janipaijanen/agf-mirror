# Note: residual surveillance and correlation risk

Lumo's sixth external review accepted the current principal-delegation design
direction, but identified three residual risks that are still cheap to exploit
outside AGF tooling:

- named principal identifiers are countable across coordination files;
- timestamps enable temporal profiling of delegation and review behavior;
- git commit metadata can be correlated with delegation grants.

I accepted these as real residual risks and updated the proposal to state them
explicitly. The proposal now recommends documenting privacy-conscious
conventions such as team aliases, rotating duty aliases, batch grants, and
retention limits. It also states the audit tradeoff: these patterns reduce
personal profiling, but they reduce reconstruction precision.

One recommendation was narrowed. Lumo suggested future CI should require no
commits authored by AI bot accounts when delegation grants are present. That is
too broad: transparent AI bot authorship can be safer than laundering AI work
through a human-looking git identity. The sharper guardrail is to reject opaque
or shared bot-account patterns and, in a future schema-visible slice, require a
linked human decision record or handoff when a delegated merge request uses a
delegation grant.

This keeps the MR as exploratory analysis. Public adopter-doc changes, such as
adding a residual-risk paragraph to `should-you-adopt.md`, should be handled by
a later Gate 1 plan if the governor-reviewer wants to turn this direction into
v2.x docs conventions.
