# Full mandatory-needs audit finds two live rule-implication defects

## Review envelope

Scope: every explicit `needs:` edge in `.gitlab-ci.yml` at `origin/main`
`86e92ad90e14fdf323211531ad0e4c9914adde65`, evaluated against the producer
and consumer `rules:` contexts and path sets

Coverage: COMPLETE for the six consumers and eleven explicit dependency edges
in the file; dynamic child pipelines and implicit stage ordering are not in
scope because this configuration declares neither as an additional `needs:`
surface

Recommendation: BLOCK a pair-only patch; plan one bounded correction of the
mandatory-needs implication class, with both reproduced mismatches and a
negative control

Blocking findings: 2

Advisory findings: 1

Open findings with accepted risk: 0

Authority: recommendation only; governor-reviewer decides Gate 1, scope, and
Gate 2

## Inventory and result

The invariant is: in every context and changed-path class where consumer `C`
is included, every non-optional producer `P` in `C.needs` must also be
included. Artifact-bearing needs make this semantic, not merely syntactic:
making the edge optional is valid only if the consumer has a tested path that
works without that producer's artifact.

| `release:verify` | `release:create`, `rust:tooling:release` | coherent: all are tag-only |

## NRI-1 — OCI MR scan has broader pipeline-source rules than its producer

`agov:oci:mr-build-scan` is eligible in merge-request pipelines, the
first/non-default branch-push fallback, later branch contexts with matching
changes, and API/web/scheduled branch contexts where `CI_COMMIT_BRANCH` and
`changes:` evaluate true. `rust:tooling:preview` is eligible only for a
merge-request event or the default branch.

The mismatch is already reproduced: `rhqb` records eight API-created
non-default branch pipelines rejected because the scan needed a preview job
that did not exist. `m2nh` correctly classifies this as the same defect shape
as !2313.

`rhqb`'s suggested one-word `optional: true` is not a complete correction.
The scan declares `artifacts: true` and `agov-oci-image.sh build-unpublished`
consumes the packaged Rust archive. An optional missing producer would allow
graph creation but would not supply the required build input. Either producer
rules must cover every intended consumer context, or consumer contexts must be
narrowed deliberately; artifact absence cannot be waived accidentally.

Resolution condition: make the producer's context/path inclusion a superset of
the consumer's intended inclusion, or remove unsupported consumer contexts,
and demonstrate both an intended non-default-branch context and an MR context
with the producer artifact present.

## NRI-2 — combined preview verifier has a broader path set than AGF preview

For MR and default-branch pipelines, `release:assets-verify-preview` is
eligible for every `tooling/rust/**/*` change. `agf:dist:preview` is not; it
names `agf/**/*`, `.gitlab-ci.yml`, two review documents, and only
`tooling/rust/scripts/check-release-self-sufficiency.sh`.

MR !2313 reproduced this mismatch with the single changed path
`tooling/rust/Containerfile.agov`; all three attempted pipelines were rejected
at graph creation, as `k6m3` records. The same mismatch exists on a
default-branch push containing only such a Rust path.

Resolution condition: make the AGF producer run whenever the combined
verifier is intended to run, or narrow/split the verifier with an explicit
statement of what proof is retained. `needs:optional` alone is invalid because
`verify-pre-oci` requires the complete AGF and Rust artifact set.

## Preferred correction shape

The smallest semantically complete design is producer parity, not optional
needs:

1. preserve the current intended consumer coverage;
2. align `rust:tooling:preview` with every intended
   `agov:oci:mr-build-scan` branch context;
3. align `agf:dist:preview` with the combined verifier's Rust path class;
4. measure the added AGF-preview runner cost before accepting that choice;
5. if that cost is disproportionate, split the verifier into independently
   meaningful artifact checks rather than silently dropping full-set proof;
6. add a deterministic check of `consumer inclusion => producer inclusion`
   for all eleven mandatory edges and the supported pipeline contexts/path
   classes, with a mutation that reintroduces each mismatch and fails.

This is a gate-mechanics correction and the A1 plan's own stop condition says
scope growth returns to Gate 1. The two reproduced platform failures are the
before-state negative evidence. After an approved correction lands, the fresh
vulnerable-base MR must both construct a valid graph and fail specifically at
the Trivy gate; only that later transcript can close A1 acceptance criterion
1. Do not spend another pipeline before the graph correction is approved and
implemented.

## Advisory learning

The recurring impact-assessment failure is reasoning about each job's path
anchor independently. A consumer rule is not safe merely because its own path
set is complete; every mandatory producer must be eligible over the same
context/path domain. After the blocker is closed, route that invariant as a
learning/control candidate rather than limiting the lesson to either job
pair.
