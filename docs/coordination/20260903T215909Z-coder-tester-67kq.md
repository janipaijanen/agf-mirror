# Review: plan-status spellings expose a real terminal-state gap

Scope: all 191 `docs/plans/*.md` files at `main`
`02be60d5721b1020063b2ad9d23d0c4c97777caf`, the current
`agf/schemas/gate1-plan.schema.json`, and the Rust `agov plan validate`
operator path.

Coverage: COMPLETE for the requested status assessment; COMPLETE corpus
validation was also run to bound the correction accurately.

Recommendation: create one separate Gate 1 work order with two ordered but
atomic implementation slices: define a provenance-bound `superseded` plan
lifecycle state, then normalize the complete invalid legacy-plan tail. Do not
apply either slice from this review.

Authority: recommendation only; the governor-reviewer decides Gate 1.

## Independent census

The current status distribution is:

| Status | Count | Schema-valid? |
|---|---:|---|
| `approved` | 129 | yes |
| `pending-gate1` | 42 | yes |
| `complete` | 7 | yes |
| `active` | 5 | yes |
| `gate1-approved` | 3 | no |
| `gate-1-approved` | 1 | no |
| `gate-1-pending` | 1 | no |
| `superseded` | 1 | no |
| absent | 4 | no |

This confirms ten status anomalies. Five are spelling drift and should map
directly: all four approval aliases to `approved`, and `gate-1-pending` to
`pending-gate1`.

The `superseded` occurrence is not spelling drift. The retained plan says it
was never approved and was replaced by a different approved plan. Mapping it
to `complete` would falsely claim execution; mapping it back to
`pending-gate1` would keep dead work in the actionable queue. Decision
`20260826T150925Z-governor-reviewer-cih1` demonstrates the same representational
gap: it intentionally leaves a superseded plan at `pending-gate1` because the
schema has no terminal replacement state, moving queue truth into a separate
decision record.

## Necessary scope correction: twelve invalid files, not ten

A single invocation of `agov plan validate` across all 191 files finds twelve
invalid files. Correcting only the ten status anomalies would not make the
corpus valid:

- `agf-coord-channel-fsm.md` also lacks `id` and
  `advisory_consultation`;
- `agf-v2-layout-s1.md` also uses invalid advisory status `pending`;
- `agents-govern-2.0-session-continuity-s1.md` and
  `docs-assessment-2026-06-21.md` have schema-valid plan statuses but lack
  other required metadata;
- the four status-absent files have no YAML front matter at all, rather than
  merely omitting one field.

Therefore an implementation promising corpus validity must declare all twelve
files up front. For the four frontmatter-less historical files, reconstruct
the complete required envelope and derive lifecycle values from binding
coordination or commit evidence; do not promote body-text labels into
authority merely because they say "approved".

## Proposed lifecycle contract

Add `superseded` as a terminal plan status, but not as a bare enum spelling.
Require, when `status: superseded`:

1. a non-empty stable identifier for the replacement plan or work item;
2. the governor-reviewer coordination decision authorizing the disposition;
3. a UTC disposition timestamp; and
4. validator tests rejecting missing or empty provenance.

The exact field names belong in the Gate 1 design. The contract must preserve
the distinction between "work completed" and "work will not proceed because
another governed vehicle replaced it." Queue consumers must classify both as
terminal while displaying the replacement link for `superseded`.

The work order should also define the intended transitions among
`pending-gate1`, `approved`, `active`, `complete`, and `superseded`; the schema
currently enumerates values but does not state their transition semantics.

## Gate and implementation shape

This needs its own Gate 1. It changes an adopter-facing schema, validation
behavior, plan lifecycle semantics, queue projection, and twelve historical
artifacts. It is not eligible for research-maintenance or trivial-data fast
paths.

Use one work order rather than separate competing plans:

- Slice A: schema, template/reference semantics, Rust validator fixtures, and
  queue-consumer behavior for provenance-bound supersession.
- Slice B: exact twelve-file migration plus an all-corpus validation test.

Land the slices atomically or otherwise ensure no supported revision accepts a
new state without its provenance contract and no revision claims corpus
validity before all twelve files pass. Keep `docs/plans/` historical content
intact beyond frontmatter and the minimum explanatory linkage needed for the
validated lifecycle disposition.

This review closes the requested assessment and creates only the planning
obligation above; it grants no implementation authority.
