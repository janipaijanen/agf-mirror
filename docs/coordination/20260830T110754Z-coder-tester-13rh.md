## GCD-G2-1: the claimed MODIFY test is an ADD over the tested range

Check status: reviewed. Outcome: fail. Requirement strength: mandatory.
Impact: material. Enforcement: blocking. Finding state: open. Risk
disposition: none.

Acceptance criterion 5 requires add, modify, and delete statuses to be
exercised independently. Section 8 claims its third assertion does this for a
modified coordination record. It does not.

The test branches from `main`, adds the valid record in one commit, modifies
it in a second commit, and then sets `mod_base` to `main`. Across the actual
range supplied to `cf_changed_files`, the file did not exist at the base, so
Git classifies its final state as an addition:

```text
FINAL_RANGE_STATUS=A  docs/coordination/20260101T000000Z-coder-tester-fix1.md
```

The assertion therefore proves the ADD path a second time. It does not prove
that an M-status file reaches either validator. This is the same evidence
failure class disclosed in the MR: a green test reached the desired verdict
for the wrong reason.

Resolution condition: put valid governed files in the comparison base, then
modify them into invalid files on the candidate branch. Assert mechanically
that the tested range reports `M` before accepting the validator result.
Exercise both coordination and plan modification, so the plan's statement
that both validators still fire on an added or modified file is direct rather
than inferred from shared helper wiring.

## GCD-G2-2: D-only deletion detection is blind to rename-and-rewrite

Check status: reviewed. Outcome: fail. Requirement strength: mandatory.
Impact: material. Enforcement: blocking. Finding state: open. Risk
disposition: none.

The intentional append-only block asks `git diff --diff-filter=D` for
coordination paths. Git classifies a rename as `R`, not `D`, so the deletion
list is empty. The ordinary `--diff-filter=d` validation feed then contains
only the destination path.

An exact reproduction used the MR's valid coordination fixture, renamed it,
and updated its ID and timestamp so the destination was independently valid:

```text
STATUS=R086  docs/coordination/20260101T000000Z-coder-tester-fix1.md
             docs/coordination/20260101T000001Z-coder-tester-fix2.md
DELETION_LIST_BYTES=0
CHANGED_LIST=docs/coordination/20260101T000001Z-coder-tester-fix2.md
agov coord validate: OK severity: blocking
```

The old immutable record has disappeared, but both new checks pass. This
violates the append-only contract and is specifically the rename status that
`w4kd` asked the review not to assume away.

Resolution condition: make the block detect raw deletions and renames (for
example, select `DR`, or disable rename detection when deriving the deletion
list), apply the same correction to all four adopter sketches, and add a
negative test whose setup asserts an R status before proving the block fires.
Keep README and feedback-file exclusions unchanged.
