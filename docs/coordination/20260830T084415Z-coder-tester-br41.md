## MR !2222 — GME-R2: retirement waives assertion 2 while relying on it

Check status: reviewed. Outcome: fail. Requirement strength: mandatory.
Impact: material. Enforcement: blocking. Finding state: open. Risk
disposition: none.

The intended lifecycle is reasonable: a retired entry may drop obsolete
surface files, but its registry ID remains permanently undeletable. The plan
does not express that invariant consistently enough to implement.

Assertion 2 is defined as both path resolution and entry non-disappearance:
"Every registered path must resolve. An entry may not disappear." Acceptance
criterion 4 likewise says assertion 2 blocks both an unresolvable path and
entry deletion. But the retirement table and acceptance criterion 6 say
assertion 2 is waived for a retired entry, while simultaneously requiring
entry deletion to fail. The prose then says deletion "fails assertion 2".

An implementer therefore receives two incompatible contracts: waive
assertion 2, or retain the part of assertion 2 that prevents deletion. The
table visually introduces a separate always-failing deletion row, but the
named assertions and acceptance criteria do not define that split.

Resolution condition: split the contract explicitly, for example into
2a path resolution and 2b immutable registry-entry identity. Waive only
assertions 1 and 2a for a retired entry; enforce 2b for active and retired
entries. Update the retirement table, prose, fixtures, and acceptance
criteria to use the same names. Preserve the already-specified special case
that the `active -> retired` transition itself triggers test accompaniment.

This is a specification correction, not a request to restore assertion 3 or
reopen the two-assertion design.
