# Fastest correct path for !806 and !807

My recommendation is to make both plans decision-ready without treating that
work as activation or as a v2.7.0 priority decision. The due-diligence
reassessment may still park either plan even after its missing consultation
evidence is repaired.

## Sequence

The two consultation tracks are logically independent, but their final evidence
is not fully parallel because both must describe the final exact plan head:

1. Run the contribution-auditor review first against the current exact heads
   (`78fd21af22961f36a7000a064dd9202a33720e7d` for !806 and
   `6cf2aac8ad0f92c5d2098faa5f4547631fbeb207` for !807).
2. A plan-specific infosec review aid may be prepared in parallel. Do not freeze
   its conclusion until contribution-auditor findings are resolved and each
   plan's final exact head is known.
3. Revalidate the final plan files and exact-head CI. If a material correction
   changes a reviewed premise, refresh the affected review rather than carrying
   forward an obsolete CLEAR result.
4. Present the complete evidence to the governor for a separate Gate 1 decision
   on each plan. Consultation completion does not approve either plan.

This sequence avoids paying for a qualitative infosec conclusion on a plan that
the contribution audit may materially change, while allowing evidence gathering
to proceed concurrently.

## Who can queue and perform the contribution audit

A governor-originated request is not required merely to ask for advisory review.
Planner-architect or coder-tester can publish the exact-head request. Binding
Gate 1 remains exclusively the governor's decision.

Because Claude authored the plans, Codex is an authorized contribution-auditor
player for this work under the cross-LLM policy encoded in
`agf/agents/contribution-auditor.yaml`; this is not Codex self-audit. A dedicated
Codex audit session is preferable for clean role and evidence separation, even
though the same-session prohibition is specifically about an author auditing
its own contribution. The audit record must name the reviewed heads and keep
contribution-guidance review distinct from later implementation-diff review.

One review record may cover both plans only if it gives separate findings and a
separate disposition for each exact head. A generic portfolio-level CLEAR is not
sufficient.

## Infosec path

Do not use a governor waiver as the default shortcut. The cheaper evidence path
is a bounded, plan-specific review aid using existing process:

- for !806, cover stdio framing and trust boundaries, mutating-command identity,
  workspace/path confinement, MCP dependency and supply-chain exposure,
  structured-error leakage, and parity with CLI authority;
- for !807, cover archive contents, sensitive-data and identity minimization,
  retention/access boundaries, discovery-file trust and instruction injection,
  and path/symlink escape behaviour;
- run the applicable local Rust `agov validate infosec` checks and cite exact
  outputs as mechanical evidence; and
- route the remaining qualitative applicability question to the governor for an
  explicit per-plan resolution.

The active infosec-sentinel is CI-backed and can supply mechanical findings; it
cannot silently convert an incomplete qualitative consultation into approval.
If the governor concludes the role cannot provide more than the bounded aid,
the resulting waiver/resolution should say so separately for !806 and !807,
rather than reusing an unrelated waiver.

## Additional decision-readiness checks

Before either plan is eligible for Gate 1, also confirm that its dependencies,
command inventory, affected-file list, and packaging assumptions still match
current `main`; both heads predate substantial tooling and release work. This is
factual re-verification, not permission to broaden scope. Any scope change must
return through the applicable plan review.

Finally, keep two decisions separate:

- **unblocked/decision-ready** means the stale or invalid consultation evidence
  has been replaced and the exact head is reviewable;
- **accepted into v2.7.0** is a portfolio and Gate 1 decision that should be made
  only after the due-diligence recommendation disposes each plan as accept,
  park, or discard.
