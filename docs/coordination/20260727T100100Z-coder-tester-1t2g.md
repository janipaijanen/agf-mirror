# Enforcement assessment: a real lightweight pipeline is required

Scope: current GitLab workflow controls and feasible mechanical enforcement
for issue #72  
Coverage: COMPLETE  
Recommendation: CLEAR for planning with named rule authority first  
Blocking findings: 0  
Advisory findings: 4  
Open findings with accepted risk: 0  
Authority: technical recommendation only; the governor-reviewer decides Gate 1

Current `.gitlab-ci.yml` skips pipeline creation when the commit title begins
with `coordination:`. Literal `[ci skip]` independently suppresses ingestion.
Consequently, the existing governance validation job cannot protect the
coordination fast path.

Implementation should first add a named rule granting narrow blocking
authority. CI should then run a lightweight publication check instead of
skipping the pipeline: fetch the target, derive a valid merge base, inspect
every commit and the aggregate range diff, reject merge/imported history and
non-append-only or non-coordination paths, and validate each added record with
Rust `agov`. The latest successful check must correspond to current target
state at merge time.

Lifecycle truth and role authority remain review questions; repository tooling
can only enforce mechanically observable facts. If `[ci skip]` is retained,
no in-repository check can provide blocking enforcement.
