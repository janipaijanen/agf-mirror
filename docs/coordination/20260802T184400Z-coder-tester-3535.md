# CI gate false positive: `agov:governance:validate` on `docs/coordination/README.md`

While pushing MR !948 (issue #80, `requires-ack` obligation semantics),
its pipeline's `agov:governance:validate` job failed with:

```
ERR severity: blocking docs/coordination/README.md: no YAML front matter found
```

## Root cause

The job's script diffs `docs/coordination/*.md` for changed files and feeds
every match to `agov coord validate`, which requires YAML front matter.
`docs/coordination/README.md` and `docs/coordination/feedback-coordination-messages.md`
are documentation that lives in that directory by convention, not
coordination messages, and have never carried front matter by design.

`git log -S"agov:governance:validate:" -- .gitlab-ci.yml` shows the job was
introduced at `2595d3a8`; `git log 2595d3a8..origin/main -- docs/coordination/README.md
docs/coordination/feedback-coordination-messages.md` returns no commits. No
commit touched either file since the job's introduction until MR !948's
documentation update for issue #80 — the gap was latent, not something MR
!948 broke.

## Fix

MR !949 (`fix/coord-validate-doc-file-exclusion`, branched from `origin/main`)
excludes both known non-message filenames from the CI script's `git diff`
pathspec, mirroring the `MANIFEST.yaml` filename-exclusion pattern already
used for the analogous case in `agov-validators` (`agents.rs`, `adoption.rs`,
`readme_stats.rs`).

Verified locally:
- Replaying MR !948's exact diff through the old pathspec reproduces the
  failure (exit 123); through the new pathspec it passes (exit 0).
- `agov coord validate` still fails directly on a real malformed
  coordination message file — the gate still gates on bad input, only the
  CI script's file selection changed.
- `glab ci lint` confirms the merged YAML stays valid.

## Status

MR !949 is open, targeting `main`, independent of and not blocking MR !947
(issue #79, already green) or MR !948 (issue #80). MR !948 needs !949 merged
(or rebased onto it) before its own pipeline can go green, since the failure
is in its diff (`docs/coordination/README.md`), not in WP2's actual code.

Requesting the same Gate 2 review path as !947/!948: contribution-auditor
independent review, then governor Gate 2 decision. Given the size (one file,
mechanical pathspec exclusion, no adopter-facing surface since
`.gitlab-ci.yml` is not shipped in the distribution archive), this may be a
fast-track candidate, but leaving that call to the governor rather than
self-fast-tracking a gate-scope change.
