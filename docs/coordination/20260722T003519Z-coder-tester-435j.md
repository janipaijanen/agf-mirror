## Row A: external release-asset boundary — composed-lifecycle evidence

`provenance::validate_discovered_assets` (new,
`tooling/rust/crates/agov/src/provenance.rs`) rejects, before any
download: unsafe basenames (`is_safe_basename`, reused from
`artifact_filename` validation — absolute, parent, separator, `.`/`..`),
duplicate names, non-https URLs, and URLs whose host does not match the
host derived from `--releases-url` itself (`parse_https_host`, a narrow
authority parser with an explicit test for the userinfo trick
`https://gitlab.com@evil.example/path` reporting the real host,
`evil.example`, not the decoy). Fails closed for the whole batch, not
per-entry.

`download_asset_safely` (new, `main.rs`) fetches bytes to memory via
`curl --output -` (curl itself never opens the destination path), then
writes via `OpenOptions::create_new` — refuses a pre-positioned symlink or
an already-existing file rather than following/overwriting it.
`post_publication_check_command` now also requires `--download-dir` be
absent or empty before it will use it, so a caller cannot point it at a
directory holding a planted symlink under a name matching a
to-be-discovered asset.

Composed-lifecycle evidence: ran the real command against the actual
published v2.3.1 GitLab Release again post-fix (15 real assets,
host-validated against real `gitlab.com`, all downloaded via the new
create_new path) — exit 0, unchanged correctness. Local-component
evidence: unit tests
`negative_validate_discovered_assets_rejects_{absolute_name,
parent_traversal_name, separator_name, duplicate_names, non_https_url,
wrong_host_url, userinfo_trick_url}`,
`negative_download_asset_safely_refuses_{preexisting_symlink_destination,
preexisting_regular_file_destination}` (the symlink test asserts the
symlink's target file was never written to, not just that the call
errored).

## Row B: published OCI chain — composed-lifecycle evidence

New `pull_and_inspect_published_oci_image` (main.rs) builds the pinned
`image_reference@manifest_digest` ref via new `provenance::oci_pull_ref`
(strips any `:tag`, never trusts a mutable tag), runs a real
`podman pull` against it, then `podman inspect`s the pulled digest-pinned
reference — this is the composed-lifecycle path, distinct from and in
addition to the existing `--oci-image` flag (which only inspects an
already-local image the caller names). `check_oci_image_evidence` is
extended to (a) require `evidence.digest.is_some()` — a missing digest is
now a finding, not a silent pass, and (b) independently compare
`record.labels.version`/`record.labels.revision` against real evidence,
not only the top-level `version`/`source_commit` fields (a record can now
be caught disagreeing with itself between the two).

Composed-lifecycle evidence, the "approved disposable/public registry
pull test": new `tests/oci_pull.rs` integration test does a real
`podman pull docker.io/library/busybox@sha256:fd8d9…` (a public image,
not this project's own registry — decoupled from this project's OCI
credentials), builds a synthetic oci-image record claiming labels
busybox does not carry, runs `agov dist validate-provenance --oci-image`
against the pulled digest-pinned ref, and asserts a real
"OCI image evidence disagreement" finding — proving the pull digest
matching mechanics and comparison logic both operate on real registry
data, not a mock. Ran it live: `cargo test -p agov --test oci_pull`,
passed against the real network.

For this project's own image: `post_publication_check_command` calls
`composed_oci_chain_check`, which runs
`pull_and_inspect_published_oci_image` + `check_oci_image_evidence` for
every downloaded `oci-image` record automatically — not optional, not
requiring a manually-supplied `--oci-image` flag. New `release:verify` CI
job (`.gitlab-ci.yml`, `quay.io/podman/stable:v5.6.0`, `needs:
release:create`) runs `agov dist post-publication-check` against the real
published release after `release:create` uploads it, so this pull

## Row C: packaged executable self-report — composed-lifecycle evidence

`composed_self_report_check` (main.rs) is called unconditionally by
`post_publication_check_command` for every downloaded `product: "agov"`
tar.gz/zip record — not left as an optional side command. It gates on
`executable_target_platform()` (maps the verifier host's real
`std::env::consts::{ARCH,OS}` to the one Rust target triple this project
actually publishes archives for and that host can run: only
`x86_64-unknown-linux-musl` on an `x86_64`/`linux` host today,
`aarch64-unknown-linux-musl` on `aarch64`/`linux`). A cross-target archive
is not silently skipped: it emits an explicit `SKIP ... target_platform
... is not executable on this verifier host` line naming the gap, so a
missing composed check is visible in the log rather than absent from it.

`check_self_report_agreement`'s commit-agreement logic now requires
either an exact string match, or both strings hex and the shorter at
least 7 characters (`MIN_COMMIT_PREFIX_LEN`, matching `git rev-parse
--short`'s own floor) with a true prefix relationship — an arbitrary
short/non-hex prefix no longer agrees.

Composed-lifecycle evidence: ran the real v2.3.1 post-publication check
end to end again post-fix — no false-positive self-report firing against
legacy records (they carry no `product` field at all, so the gate
correctly no-ops; verified by inspecting the downloaded record directly,
not assumed). Local-component evidence:
`negative_self_report_commit_{prefix_shorter_than_minimum,
non_hex_prefix}_is_rejected`, `executable_target_platform_returns_a_known_triple_or_none`.
I have not run `composed_self_report_check` against a real *v2.4* tooling
archive end to end (no v2.4 release exists yet to download) — the
existing `self_report_round_trip_through_{tar_gz,zip}_extraction` tests
and the `positive_download_asset_safely_writes_fresh_destination` test
cover the extraction and download primitives independently, but the full
composed chain (download real v2.4 archive -> extract -> execute -> compare)
will only get first real-release evidence when v2.4.0 actually ships.
Flagging that gap explicitly rather than implying it is already closed.
