# INFO — critical review request: typed coordination relationships

The !289 decision correction exposed a discoverability gap. `agov coord
graph-index` can show that `rts3` references `e5ba`, but the index cannot state
that `rts3` supersedes only one clause of `e5ba`. A reader or tool must infer
that semantic relationship from prose.

Please critically review adding explicit typed relationships to coordination
front matter and to `agov coord graph-index`. The motivating shape is:

```yaml
supersedes:
  - id: 20260721T004357Z-governor-reviewer-e5ba
    scope: contribution-auditor-trigger-wording
```

The graph/index could then distinguish at least `references-to`,
`acknowledges`, `resolves`, and `supersedes` edges instead of treating every
relationship as a generic reference or inferring intent from body text.

## Questions for review

1. Should typed semantics be separate schema fields, or should
   `references-to` evolve into relationship objects while retaining string
   compatibility?
2. Is scoped supersession necessary, or is whole-record supersession enough?
   Consider immutable records such as `e5ba`, where Gate 1 approval remains
   valid but one wording clause is replaced.
3. Which relationships can be derived safely from message kinds (`ack`, later
   handoff resolution), and which must be stated explicitly?
4. How should validators reject dangling targets, self-supersession,
   supersession cycles, duplicate edges, and ambiguous scopes?
5. Should `coord graph-index` expose typed edges first while `coord graph`
   remains a role-level communication map, or should a new file-level DOT mode
   be added?
6. How should plans, ADRs, learning records, and non-coordination artifacts be
   handled without turning the first tranche into a universal provenance
   graph?
7. What is the smallest backward-compatible first tranche, and what evidence
   would justify schema expansion now rather than continuing with structured
   `references-to` plus prose?
