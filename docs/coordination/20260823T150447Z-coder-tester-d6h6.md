# Codex recommendation: shared idle-work discovery rule

The governor requested an AGF development rule shared by all supported AI
assistants: when an assistant finds no open assignments, it should propose
next actions from the backlog, TODO list, or otherwise open issues and merge
requests.

## Verified current-state distinction

The rule's fallback does **not** trigger for the current coder-tester session.
`agov session resume --role coder-tester --base-branch main` reports three
ready handoffs: `reactivation-staffing-final-rereview`, `v261-round3-review`,
and `get-started-commissioning-slice-b-implementation`. This is useful design
evidence: "no new activity" and "no open assignments" must not be treated as
synonyms.

## Recommended normative contract

Add a narrowly owned workflow rule, provisionally named
`agf/rules/workflow/unassigned-work-discovery-rule.md`, applying to every AI
assistant loaded through AGF. The rule should require the following behavior:

1. Verify the queue is actually empty across published coordination,
   role-specific handoffs and pending acknowledgements, active claims, and
   already-running owned work. Reconcile stale mechanical entries before
   declaring the queue empty.
2. Inspect the project's governed planning/backlog and TODO surfaces, then
   paginated open issues and merge requests. Repository-defined priority,
   milestone, dependency, security, and gate signals take precedence over
   recency or ease.
3. Propose a small ranked set of actionable candidates. Each candidate should
   name its source artifact or forge ID, expected value, role fit, current
   gate, dependencies/blockers, and the specific approval or assignment still
   needed.
4. Keep proposals advisory. An empty queue does not authorize claiming a
   candidate, changing files, opening or merging an MR, expanding scope, or
   bypassing Gate 1/Gate 2 and role authority.
5. If no credible candidate exists, report the surfaces checked and the
   absence of candidates rather than manufacturing work.

## Placement and projection recommendation

A separate workflow rule is clearer than extending
`agent-improvement-proposal-rule.md`: that existing always-rule governs
incidental improvement observations during assigned work, while this proposal
governs task discovery only after assigned work is exhausted.

The canonical rule should own the normative language. The
`poll-and-coordinate` operating page and skill should gain concise pointers or
bounded operational steps, not duplicate the rule. Update `agf/rules/README.md`
for discoverability. The Gate 1 plan must include the six-row projection screen
and structured evidence required by
`documentation-rule-projection-rule.md`; existing loaders already instruct
assistants to read `agf/rules/`, but the plan should explicitly verify that
this remains sufficient for every shipped assistant surface.
