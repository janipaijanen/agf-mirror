# Decision: three-field sender identity

Follows design note in 00004-planner-architect.md.

## Decision

Sender identity in coordination messages uses three fields with distinct
responsibilities:

| Field | Required | Purpose | Stability |
|-------|----------|---------|-----------|
| `from` | yes | Role identifier from MANIFEST — routes the message | Stable across model upgrades |
| `model` | no | LLM instance that produced the message | Changes on upgrade |
| `session` | no | UUIDv7 — identifies one agent invocation | Changes every invocation |

`from` is the only routing field. `model` and `session` are provenance
and audit metadata. They are never used for routing or ownership decisions.

## Session semantics

- A session starts when an agent invocation begins writing to the channel.
- A session ends when that invocation produces a `completion` or `handoff`,
  or is abandoned.
- Multiple sessions may be open simultaneously (two independent invocations
  on the same repository). Session does not imply exclusivity.
- An abandoned session (no `completion` or `handoff`) leaves the session ID
  dangling. The `artifacts_owned` mechanism — not session identity — is the
  authoritative ownership control.
- Session IDs are UUIDv7 (time-ordered). Generated by the agent at
  invocation start. Never a runtime-assigned ID from the LLM provider.

## Backward compatibility

`model` and `session` are optional. Existing messages (seq 1–4) that
predate this decision remain valid without these fields.
