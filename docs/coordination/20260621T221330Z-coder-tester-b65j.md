# Gate 2 handoff: dependency CVE scan in GitLab CI

## Summary

Adds an explicit GitLab CI job, `dependency:cve-scan`, using Trivy filesystem
vulnerability scanning.

The job scans committed dependency manifests and lockfiles, including Rust
`Cargo.lock` and Elixir `mix.lock`, without building project artifacts. It
keeps a JSON report for review and blocks on fixed HIGH or CRITICAL findings.

This complements the existing `rust:tooling:deny` job. `cargo-deny` still
checks RustSec advisories and license policy for Rust changes; the new Trivy
job is a more visible cross-dependency CVE scan for GitLab pipelines.

## Sources checked

- Trivy filesystem scanning documents lockfile-based vulnerability scanning.
- Trivy language coverage lists Rust `Cargo.lock` and Elixir `mix.lock` as
  supported for filesystem/repository scanning.
- GitLab dependency scanning docs show GitLab's native SBOM approach supports
  Cargo package URLs, but the built-in GitLab dependency scanning feature is
  tier/instance dependent. This branch therefore adds an explicit Trivy job
  rather than relying only on GitLab's managed security template.
