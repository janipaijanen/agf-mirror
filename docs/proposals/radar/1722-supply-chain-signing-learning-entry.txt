    description: >
      An external open-source due-diligence simulation (ChatGPT run,
      Protocol 2.1, 2026-08-17), filed as risk R5 ("Supply-chain
      compromise or unverifiable publisher identity", rated High) and
      finding F6, observed: 0 of 4,180 commits and 0 of 39 tags in this
      repository are cryptographically signed (22 tags annotated, 17
      lightweight, none signed); no SBOM (CycloneDX or SPDX) is
      published for any binary, container, or source release; and the
      project's existing release provenance (checksums, self-reported
      commit/build metadata) is same-channel, self-issued metadata —
      useful for detecting accidental corruption in an independently
      downloaded artifact, but not sufficient to authenticate publisher
      identity or establish build provenance to a third party. The DD's
      own framing, quoted directly: "Self-issued hashes and provenance
      detect accidental corruption when distributed independently, but
      same-channel metadata does not authenticate publisher identity or
      establish build provenance."

      Following the OD-1 correction on the companion R8/operational-
      debt learning (`20260817T202241Z-ookv`, per coder-tester review
      `20260817T202807Z-coder-tester-37mj`), this entry cites the

      **MR !1691 is not yet merged to `main` as of this record** — this
      dependency is stated explicitly, not implied, per the same OD-1
      resolution condition.

      This is a distinct remediation from the tooling-license MIT fix
      and from the R8 operational-debt thread: signing establishes
      *who* published an artifact and that it has not been altered
      after signing; an SBOM establishes *what* is inside a released
      artifact (dependency inventory) for downstream vulnerability and
      licence-compliance scanning. Both are release-engineering gaps,
      not governance-record gaps, and both are currently zero — no
      partial signing, no partial SBOM coverage exists to build on.
