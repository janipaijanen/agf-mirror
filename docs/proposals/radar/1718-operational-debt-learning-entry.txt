      "547 branches" likewise mixes active, merged, historical,
      review, plan, protected, and evidence-preserving branches without
      age/disposition buckets. This entry no longer asserts these counts
      as a validated rate problem — see the corrected recommendation
      below.

      This project does have an active, deliberate response to *part*
      of this problem: GitLab issue #110 and its Gate 1 plan
      (`docs/plans/20260816T114725Z-open-mr-hygiene-disposition.md`,
      MR !1617) triage open merge requests one at a time, with a
      corrected verification methodology (merge-base diff + unique
      content-identifier search, not path existence, since shared
      accumulator files like `agf/learnings/foundry.yaml` and
      `docs/radar.md` make path-only checks unreliable) after an
      earlier, less rigorous pass
      (`20260811T212756Z-planner-architect-rhrj`, 2026-08-12) closed 20
      already-agreed dead MRs but left the underlying queue largely
      intact. Issue #110's own bounded first round (Gate 1 activated
      2026-08-16 under the standing `tgjs` conditional mandate,
      executed, Gate 2 accepted `ahh2`) closed exactly one MR (!921).

      What has no plan at all, as of this record: a closure SLO for
      pending handoffs/acknowledgements, a bounded maximum branch
      lifetime, a recurring (not one-off) drift-closure process for the
      51 rule-copy findings, or any dashboard/ownership assignment for
      tracking queue health over time. The existing response is
      deliberately narrow, bounded, per-item, and manual by design (to
      avoid the blanket-closure risk of destroying real unpublished
      backlog) — but that same design does not itself distinguish a
      live obligation from a stale or already-resolved projection in
      the tooling's own reported counts (per the `37mj` correction
      above). Whether the *rate* of accumulation is actually a problem,
      versus the *reporting* being noisy, is exactly what a measurement
      baseline (not yet built) would establish — this entry does not
      claim to already know which.
