# Plan: AGF v2.4.2 — public experience and evidence presentation

## Decision and release character

Prepare v2.4.2 as a governed **patch** release addressing the public-facing
findings from the post-v2.4.0 marketing/UX/accessibility audit, per issue
#58 (milestone `v2.4.2`, Level 1 Planned candidate) and governor decision
`qkks` (`20260723T022449Z-governor-reviewer-qkks`, splitting this work out of
the former #57/v2.5.0 discovery portfolio because !350/!354/!402 already
provide the most mature evidence base among those themes, the likely work is
low-risk and reversible, and public-content freshness has a time cost).

This is corrective and presentational work on already-shipped public
surfaces: fixing factual/trust defects, reducing duplication, improving
information architecture, and making assistant identity visible on shared
GitLab accounts. It does not add a capability, schema field, role, tool, API
surface, or adopter-facing contract. See "Patch-version justification" below.

## One coherent public user outcome

**A first-time evaluator reads the homepage and forms an accurate,
proportionate impression of what AGF is, what it costs, and whether the
project's own internal claims are consistent with each other** — without
being asked to evaluate command-level tooling detail before they've seen
what they get, without reading a data-handling claim the project's own rules
contradict, and without being told every command is equally mature when they
aren't. A returning reader or contributor can tell, at a glance in a GitLab
issue or MR thread, which assistant or human wrote a given note.

**Non-goals:** this plan does not redesign the site's navigation structure,
does not implement the full `1a7k` visual-semantics specification, does not
create distinct GitLab service accounts, and does not touch #53's CI/build
scope. It does not attempt to resolve every WARN/INFO item carried forward
above — only those confirmed still-live and patch-compatible during
implementation.

**Stop conditions:** if reconciling the carried-forward WARN/INFO items
surfaces a defect requiring a schema, role, tooling/API, or adopter-contract
change, that item is split into its own issue and plan rather than expanding
this patch's scope — matching the standing constraint v2.4.1 used for the
same situation.

## Assistant-attribution byline — implementation scope

Per `3d27`: apply `### <Execution identity> · <AGF role>` (e.g. `### Claude ·
planner-architect`) as the first heading on assistant-authored GitLab
issue/MR notes and descriptions going forward. When a note bridges a durable
coordination record, name that record's ID near the byline. State the
platform boundary explicitly wherever the convention is documented
(byline ≠ authentication ≠ non-repudiation; GitLab's native author field
remains the shared account). This is a documentation/convention change (a
`CONTRIBUTING.md`-style note or an addition to an existing process page) plus
retroactive application going forward in this project's own coordination
practice — not a schema, tool, or code change, so it stays patch-compatible.
No account creation, no credential provisioning.

## Patch-version justification

Every change in scope:

- corrects a factual/trust defect (BLOCK 1-4), removes duplication that has
  already drifted (item 5), improves placement/altitude of existing content
  (item 6), adds a cross-reference link to already-existing content (item 7),
  or adds a documentation convention for existing GitLab activity (item 8);
- adds no new schema field, role, tool, CLI flag, MCP surface, or
  adopter-facing contract;
- touches only prose, the homepage table, figure DOT sources (legend/color/
  terminology, not new figures), and cross-reference links under
  `agf/docs/site/` and `agf/docs/figures/src/`.

If any carried-forward WARN/INFO item, once re-verified, requires a schema,
role, tooling/API, or adopter-contract change, it is split out of v2.4.2 into
its own separately-scoped issue — this is a standing implementation
constraint, not merely a note, matching v2.4.1's own binding language.
