# Plan: reclaim v2.4.4 as the next real release

## Trigger and decision sought

The governor directed the project to proceed with v2.4.4 if feasible, or move
v2.4.5 content into v2.4.4 when that is more feasible. The current numbering
split is administrative rather than technical:

- v2.4.3 is the latest published release;
- MR !490 reserved v2.4.4 for a procedural trial but remains `pending-gate1`
  and contribution-auditor BLOCKED it as an empty release placeholder;
- the v2.4.5 content assessment was approved only because MR !490 had claimed
  the preceding number; and
- no v2.4.4 or v2.4.5 release branch, version bump, or tag exists.

This plan reclaims v2.4.4 as the next naturally occurring release. It does not
renumber an existing tag or artifact.

## Feasibility disposition

The fastest defensible release is **not** to import the unfinished mandatory
multi-LLM review workstream from the v2.4.5 assessment. That would delay v2.4.4
and falsely make incomplete reviews release content.

Instead:

1. retire MR !490's exclusive claim on v2.4.4;
2. preserve its stable-SHA trial concept as a standing, separately governed
   measurement that may observe a future eligible release only after MR !459's
   evidence is durably landed and approved;
3. assign v2.4.4 to the concrete post-v2.4.3 documentation/release-hygiene
   baseline already merged on `main`, plus the public-version-truth
   implementation only if it clears its own exact-SHA Gate 2 before the cut;
4. retain the standardized multi-LLM review and its accepted remediations for
   v2.4.5; and
5. treat other open work as excluded unless it independently clears Gate 2
   before the frozen v2.4.4 cut and the governor explicitly adds it.

## Frozen v2.4.4 objective

v2.4.4 is a documentation provenance and release-hygiene patch. Its required
release-specific outcome is:

- public documentation distinguishes `agf/VERSION`, immutable latest-release
  tag/commit, and mutable Pages branch/commit without presenting development
  documentation as an immutable release.

The release branch is not cut until the approved
`public-version-and-docs-provenance` implementation is merged after Gate 2 and
the rebuilt Pages result is verified. If that implementation returns to Gate 1
because tag derivation is infeasible, v2.4.4 waits; it is not cut with a known
version-truth defect.

Already-merged post-v2.4.3 changes remain ordinary `main` baseline and ship
because the release branch is cut from `main`; they are not retroactively
reclassified as required release workstreams. This includes status-banner
decoupling and the public feature summary.

## Supersession and preservation

- MR !490 should be closed as superseded only after this plan receives Gate 1.
  Its blocked plan is not merged to `main`.
- The approved `v2.4.5-next-unplanned-release-assessment` remains historical
  evidence of the prior numbering decision, but this plan supersedes its
  version assignment and sequencing where they conflict.
- A short amendment after this plan's Gate 1 must update the v2.4.5 assessment
  to say v2.4.4 is no longer owned by MR !490 and that v2.4.5 retains the
  standardized multi-LLM review workstream.
- MR !459 is not a v2.4.4 release dependency. Its evidence and the stable-SHA
  trial remain separate issue #53 work; no measurement claim is made from this
  release unless that work later clears its own gates before the cut.

## Release sequence after Gate 1

1. Complete the approved public-version-truth implementation, tests, rendered
   extraction evidence, independent fact-check, and governor Gate 2.
2. Merge that implementation and verify the default-branch Pages deployment.
3. Freeze the exact `main` SHA and inventory all changes since tag v2.4.3.
4. Fact-check the frozen inventory and draft exact v2.4.4 changelog text.
5. Create `release-2.4.4` from the frozen `main` SHA.
6. On that branch only, bump `agf/VERSION` and all governed version surfaces to
   `2.4.4`, add changelog/release metadata, and make no unrelated product
   change.
7. Open the release MR; run the full distribution, strict-docs, provenance,
   tag/VERSION, artifact, and exact-SHA review path.
8. Governor-reviewer makes Gate 2 on the exact release MR SHA.
9. Merge, then tag the resulting `main` merge commit `v2.4.4` and push the tag
   immediately as required by the release-via-MR rule.
10. Verify release archives, hashes/provenance, release page, supported `agov`
    binaries, tagged source, and public docs identity.

## Explicit boundaries

- No implementation, release branch, version bump, tag, or MR closure occurs
  under this pending plan.
- Do not merge incomplete v2.4.5 review artifacts into v2.4.4.
- Do not create an artificial release merely to run the issue #53 trial.
- Do not change protected-tag/project settings in this workstream.
- Do not call mutable Pages output the frozen release documentation.
- Promotion remains parked until the public version tuple is verified.

## Gate requests

- Contribution-auditor reviews the numbering reconciliation, concrete content
  boundary, supersession language, and release prerequisites.
- Governor-reviewer Gate 1 approves or blocks reclaiming v2.4.4 and the stated
  sequencing.
- The eventual exact release MR requires independent fact-check and governor
  Gate 2; this plan does not pre-approve either.
