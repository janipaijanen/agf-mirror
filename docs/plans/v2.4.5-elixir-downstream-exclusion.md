# Plan: exclude Elixir and Mix artifacts downstream in v2.4.5

## Decision and current state

The governor-reviewer directed that `tooling/elixir/mix.lock`, and Elixir
implementation artifacts generally, must not ship downstream and that the
removal be planned for the next release, v2.4.5.

The legacy implementation has already been removed from the tracked main tree:
`tooling/elixir/` does not exist at this plan's baseline. This plan therefore
does not propose another source deletion. It closes the remaining operational
reference and makes the downstream exclusion a mechanically tested invariant.

At the baseline, shipped Rust `agov coord brief` output still inserts
`tooling/elixir/mix.lock` into generated `handoff.do_not_touch` lists in both
text and structured rendering paths. The AGF release manifest uses an explicit
allowlist and does not currently package `tooling/`, but it does not express a
specific Elixir/Mix deny rule for future manifest expansion.

## Scope

### 1. Remove the stale generated path

- Remove `tooling/elixir/mix.lock` from every Rust `agov coord brief` output
  path, including Markdown and structured output.
- Audit Rust CLI help, templates, fixtures, and current operator documentation
  for instructions that direct users to an Elixir or Mix implementation.
- Add regression tests proving newly generated coordination records contain no
  Elixir/Mix implementation path.

### 2. Establish a downstream packaging invariant

- Extend the AGF distribution policy so candidate contents are rejected if
  they contain `tooling/elixir/**`, `mix.exs`, `mix.lock`, `*.ex`, or `*.exs`.
- Apply an equivalent file-list assertion to every shipped `agov` archive.
  Platform archives remain Rust-binary distributions.
- Inspect completed AGF and `agov` candidate archives before publication; a
  forbidden member must fail the release job before checksums, provenance, or
  release publication.
- Keep allowlisting as the primary packaging boundary and add these explicit
  rejects as defense in depth against later manifest or job expansion.

### 3. Prove the gate blocks the forbidden content

- Add a negative self-test that injects at least one representative Mix file
  and one Elixir source file into candidate packaging input and proves the
  build/validation path rejects them.
- Add positive archive-list tests proving normal AGF and Rust tooling archives
  still build and contain no forbidden members.
- Ensure text and structured `coord brief` tests cover the stale `mix.lock`
  regression independently of packaging tests.

### 4. State the supported boundary

- Update the relevant distribution/release documentation to state that
  downstream executable tooling is Rust-only and Elixir/Mix implementation
  artifacts are forbidden from release payloads.
- Historical changelog entries, ADRs, completed plans, and dated evidence may
  truthfully mention the former Elixir implementation. They are not executable
  Elixir payloads and must not be rewritten to erase provenance.
- Generic documentation examples that merely discuss Elixir as an adopter's
  possible project language are also outside this removal, provided they do
  not instruct adopters to use AGF's retired implementation.
- Historical test evidence outside release payloads may retain an original
  command path when provenance requires it; it must not enter an AGF or `agov`
  distribution archive.

## Expected implementation surfaces

- `tooling/rust/crates/agov/src/main.rs` and focused `coord brief` tests
- `agf/dist/release-manifest.yaml` and distribution-manifest tests
- `.gitlab-ci.yml` and/or existing release archive verification scripts
- the relevant adopter-facing distribution/release documentation

Exact test files may narrow during implementation. Any broader removal of
historical records, or any change to supported language policy beyond release
payload hygiene, requires a new Gate 1 decision.

## Acceptance criteria

1. Text and structured `agov coord brief` output contain no
   `tooling/elixir`, `mix.lock`, or other retired implementation path.
2. No AGF distribution archive or `agov` platform archive contains
   `tooling/elixir/**`, `mix.exs`, `mix.lock`, `*.ex`, or `*.exs`.
3. A negative packaging test injects forbidden Mix and Elixir members and
   fails closed before publication.
4. The explicit distribution allowlist remains intact; the new deny checks do
   not broaden packaged source.
5. An operational-reference audit distinguishes current instructions from
   truthful historical records and reports any retained exception.
6. Rust formatting, linting, focused tests, full workspace tests, distribution
   validation, and the relevant GitLab pipeline are green at the exact Gate 2
   review head.
7. v2.4.5 release evidence includes archive member listings or equivalent
   deterministic output demonstrating the invariant for every published
   payload.

## Exclusions and sequencing

- No implementation begins until governor-reviewer Gate 1 approval.
- This plan does not bump versions, tag v2.4.5, or publish a release.
- It does not delete or falsify historical changelog, plan, ADR, learning, or
  evidence records.
- The eventual implementation must merge before the v2.4.5 release content is
  locked and packaged.
