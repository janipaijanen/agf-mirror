# RUW: deliver the v2.10.0 autonomous-development release

## Decision requested at Gate 1

Approve a release work order that closes the post-v2.9.0 release-under-work
(RUW) around one coherent outcome: AGF development assistants discover and
advance authorized work autonomously within gates, while the bounded
Improvement Propeller finds valuable follow-on work without gaining priority,
implementation, or gate authority.

`v2.10.0` is a **semantic candidate**, not an allocated namespace; the required
schema field records that provisional candidate. The merged universal-polling
rule makes the SemVer delta MINOR-shaped because it is backward-compatible
framework functionality, while its downstream-impact classification remains
**BREAKING** for direct adopters because it adds a new MUST-level assistant
duty. RUW-1 changelog and migration prose must state both axes. The version
becomes allocated only after the reversible preflight in this plan succeeds
and the release-metadata MR is ready to commit. No release candidate is created
merely to discover validation, build, security, or namespace failures.

This plan is the release work-order and publication owner. It does not replace
the already approved Propeller plan, self-approve issue #120, approve Gate 2,
or authorize a tag before the release MR merges.

## Reversible release preflight — before namespace allocation

After all mandatory work merges, create a clean disposable worktree at the
candidate `main` SHA. Apply the proposed version metadata **without committing
and without creating a tag**. Before running it, an authorized Maintainer must
create the exact `v2.10.0` protected-tag rule with Maintainers-only create
access, matching the established per-version policy. Creating that reversible
policy guard is not permission to create the tag. The preflight must:

1. Recompute and record the exact `v2.9.0..<candidate-base>` commit/path
   inventory and bind every adopter-visible change to its plan, Gate 2/merge
   evidence, changelog entry, and documentation impact.
2. Derive live current-version cells by validator/schema semantics. At minimum
   inspect `agf/VERSION`, both AGENTS loaders, the learning template and live
   adoption metadata, project manifest, every shipped agent definition
   including Improvement Propeller, `agf/ADOPTING.md`, Rust manifests/lockfile,
   governance manifest, public roadmap/release-status prose, and both
   changelogs. Historical incident/evidence text remains byte-identical.
3. Fail if a required metadata path lies outside the release allowlist below;
   expand the list only through a Gate 1 plan amendment before editing it.
4. Run umbrella, agents, assistant-loader, adopter-docs, projection, infosec,
   release-path, distribution validation/build, complete Rust tests, relevant
   negative/mutation tests, and `git diff --check` against the uncommitted
   draft.
5. Using the finalized command set delivered by the #120 child, authoritatively
   prove absence of the exact Git tag, GitLab Release, generic package version,
   and the OCI reference derived from the same helper publication uses. The
   generic-package query must page every API status that can occupy the exact
   name/version, including default, hidden, processing, error,
   `pending_destruction`, and deprecated states. An unavailable status,
   incomplete page walk, unenumerable state, or other API ambiguity is failure,
   not absence.
6. Read the exact protected-tag policy required for the candidate tag. Any
   mismatch or missing protection stops before a version is allocated.

A failed preflight is discarded as an unversioned working-tree draft. It burns
neither an RC nor a stable version number.

## Publication sequence

1. Freeze a green `main` SHA after all mandatory packages and coordination
   needed to reconstruct their gates are visible.
2. Complete the reversible preflight above.
3. Create `release-2.10.0` from that exact SHA and commit only the proven
   allowlist changes. Open a standard MR to `main`.
4. Require exact-source/target identity, complete local evidence, canonical
   exact-head pipeline, independent release-diff review, and binding governor
   Gate 2. Target drift invalidates the inventory and preflight.
5. Immediately before tagging, rerun the #120 command set over all four
   namespaces, including every enumerated generic-package status, and re-read
   protected-tag policy, source/target/merge identities, and the merged tree.
   Any drift, non-absence, incomplete pagination, or ambiguity stops.
6. Create one annotated `v2.10.0` tag on the proven merge commit and push it
   immediately. The merged release MR is the tag authorization; do not create
   or move the tag earlier.
7. Bind tag object and peeled commit to archives, checksums, provenance,
   package, and OCI digest. Verify anonymously downloaded bytes and public
   release metadata. Record completion or a forward-only failure response.

## Impact, migration, and rollback

- **Foundry:** universal polling becomes the routine operating model and the
  optional Propeller is launched through a real bounded schedule. Release work
  gains the #120 namespace guard.
- **Direct adopters:** MINOR additive governance capability plus a new MUST
  polling duty already documented by !2463. Propeller remains optional until
  an adopter explicitly staffs and activates it. The release-rule change from
  #120 adds a pre-tag obligation and must include migration prose.
- **Downstream:** assistants may create more timely, deduplicated proposals and
  coordination; no assistant receives approval, priority, merge, release, or
  destructive authority. Release operators gain fail-closed namespace checks.
- **Migration:** update loader/rule distribution; choose whether to activate
  Propeller; configure a real wake path and cursors if activated; add the
  standard pre-tag namespace proof to release operations.
- **Rollback:** before tagging, abandon the release branch and fix forward in
  ordinary MRs. After tagging, never move/delete the tag; supersede with a new
  version. Propeller can be paused by stopping its heartbeat and recording a
  governed suspended state without deleting historical proposals.
