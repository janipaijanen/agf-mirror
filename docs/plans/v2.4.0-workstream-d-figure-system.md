# Plan: v2.4.0 Workstream D — figure system and responsibility-labelled text blocks

## Intent

Bring every current public documentation figure — DOT-sourced diagrams,
inline Mermaid diagrams embedded in Markdown, and the academic SVG/PDF
figures — into compliance with the umbrella plan's required outcomes:
legend accuracy, one semantic responsibility palette, colour-independence,
the nutshell-flyer placement fix, and restrained responsibility-labelled
text blocks. Per the umbrella plan, this workstream remains a release
blocker regardless of inventory size; any deferral requires an explicit
governor decision and an amended umbrella plan, not silent scope
reduction.

## Scope boundary: what counts as "public documentation" here

The umbrella plan's language ("public documentation figures," "academic
SVG/PDF") is not self-defining once the actual tree is inventoried. This
plan draws the boundary from the project's own
`documentation-audience-rule.md` (README.md → developers;
`docs/**` public site → business users/administrators) and from what the
site build (`agf/docs/build/mkdocs.yml`, `docs_dir: ../site`) actually
publishes:

- **In scope**: every figure embedded in or generated for
  `agf/docs/site/**/*.md` (the mkdocs-built public site, `docs_dir`),
  plus the academic paper's SVG/PDF figures at `docs/academic/figures/`
  (explicitly named in the umbrella plan).
- **Flagged, not silently included**: `agf/framework.md` and
  `agf/docs/agent-communication-0.26.0.md` each contain one Mermaid
  diagram but are **not** under `agf/docs/site` and are not built into
  the mkdocs site — they are repository-root design/governance documents,
  same audience class as `README.md` under `documentation-audience-rule.md`
  (developers reading the repo directly, not the hosted public site).
  Recommend excluding them from this workstream's mandatory scope on that
  basis, but flagging explicitly rather than omitting silently, since the
  umbrella plan's wording could be read either way. **Open design decision
  1** below.
- **Explicitly excluded**: `agents-govern/framework.md` and
  `agents-govern/docs/agent-communication-0.26.0.md`. `agents-govern/` is
  a separate top-level tree from `agf/` (confirmed: it has its own
  `README.md`, `GOVERNANCE.md`, `LICENSE`, `framework.yaml` — a distinct
  project root, not a subdirectory of this project's public site). Not
  built by `agf/docs/build/mkdocs.yml`. Out of this workstream's scope
  entirely, not merely deferred.
- **Excluded, correctly, per the umbrella plan itself**: framework source
  archives and anything already superseded/historical (matches the
  existing pattern in Workstream A's "historical artifacts untouched"
  boundary).

### Class 5 — Responsibility-labelled text blocks (net-new requirement, not a figure fix)

Precedent already exists: `agf/docs/site/docs/index.md` (lines 12-25)
already prose-labels **Human decision**, **AI-operator instructions**,
**Shared concept**, and **Reference** — three of the umbrella's five
target labels, under slightly different names (**AI-operator
instructions** vs. the umbrella's **AI action**; **Automated check** has
no existing analogue found anywhere in a targeted grep across the site).
`first-governed-change.md` independently uses **"Human decision — no AI
substitute"** as an inline per-step label, a second, narrower usage
pattern already in production. Disposition: **extend existing pattern**,
not invent one — standardize on the umbrella's five exact label strings
(Human decision, AI action, Automated check, Shared concept, Reference),
reconcile `docs/index.md`'s "AI-operator instructions" wording to "AI
action," and add "Automated check" as the one genuinely missing label
class, used only where responsibility changes or ambiguity is likely per
the umbrella's own restraint requirement.

## Open design decisions (for Gate 1 approval, not implementer discretion)

Gate 1 decision `20260722T091729Z-governor-reviewer-m4tq` approves the
recommendations below as proposed: exclude the two non-MkDocs Mermaid
documents, apply the shared palette to Mermaid as well as DOT figures, and
sequence implementation through class-scoped merge requests. The
contribution-auditor findings remain explicit Gate 2 review points rather
than being represented as resolved by this approval.

1. **Are `agf/framework.md` and `agf/docs/agent-communication-0.26.0.md`
   in scope?** Recommend **no** — not part of the mkdocs-built public
   site (`docs_dir: ../docs/site`), same audience class as `README.md`
   under `documentation-audience-rule.md`. If the governor disagrees,
   these add 2 more Mermaid diagrams (1 each) to Class 4's inventory,
   with the same disposition pattern.
2. **Does cross-figure palette parity extend to Mermaid (Class 4), or do
   DOT-sourced figures (Classes 1/3) and Mermaid diagrams get separate,
   internally-consistent-only palettes?** Recommend: same palette
   everywhere achievable — Mermaid's `classDef` mechanism can reproduce
   arbitrary hex colours, so there is no technical reason to exempt it.
   Flagging as a decision rather than an assumption because it changes
   Class 4's redesign scope materially.
3. **Sequencing within Workstream D.** Given 9 DOT figures + 1 flyer + 5
   academic figures + 4 Mermaid files + the text-block standardization,
   recommend splitting into reviewable MRs by class (Class 2 first —
   smallest, highest umbrella-plan visibility; then Class 1's
   `docs-audience-map` — smallest DOT change; then the remaining Class 1
   figures; then Class 3; then Class 4; then Class 5 last, since it
   depends on the label vocabulary being finalized). Per the umbrella
   plan, none of this may be silently reduced in scope — this is a
   sequencing proposal, not a de-scoping one.

## Acceptance tests

1. Per-figure: rendered output (SVG/PNG/Mermaid-rendered HTML) uses only
   colours from the single agreed palette; a script or manual grep
   confirms no hex value outside the agreed set appears in any figure
   source file in scope.
2. Per-figure: every legend swatch's shape/line-style matches the actual
   node/edge shape used in the figure body (manual visual check per
   `visible-artifact-verification-rule.md` — this is exactly the class of
   defect that rule's Part B exists to catch).
3. Colour-independence: each figure remains interpretable with colour
   removed (greyscale render) — shape, label, or border must carry the
   same distinction color currently carries alone.
4. `docs/index.md` and `agf/docs/site/index.md`: nutshell flyer no longer
   renders full-size inline; a thumbnail or download link is present
   instead.
5. `docs-audience-map`: either removed with no loss of the categories
   already stated in adjacent prose, or replaced with a native HTML/table
   treatment — both satisfy the umbrella's requirement; confirm whichever
   is chosen still names all four (or five, per Class 5) categories.
6. Desktop, narrow/mobile, light, dark, print/greyscale, and
   screen-reader-semantics spot check per figure touched, per the
   umbrella's required outcomes — recorded as a checklist in each Class's
   Gate 2 handoff, not assumed.
7. Responsibility-labelled text blocks: grep confirms the five umbrella
   label strings are used consistently (no stray "AI-operator
   instructions" wording surviving post-reconciliation) and are not
   present around ordinary prose (spot-check count stays low/restrained,
   not blanket-applied).

## Rollback

Each class-scoped MR is independently revertible — figure source and
generated output are the only files touched; no schema, no code, no
migration. Reverting restores the prior SVG/PNG/Mermaid rendering with no
data loss.

## Risks

- **Size.** This is the largest of the three remaining release-blocking
  workstreams by file count (9 DOT figures + flyer + 5 academic figures +
  4 Mermaid files + site-wide text-block pass). Mitigated by the
  class-scoped sequencing in Open design decision 3 — each class is
  independently reviewable and mergeable, so partial progress is real
  progress, not one large unreviewable branch.
- **Subjective redesign scope creep.** The umbrella plan's own advisory
  consultation already flagged this (contribution-auditor WARN,
  "consistency pass could become unbounded subjective redesign").
  Mitigated by this inventory being closed (every figure enumerated, no
  "and similar figures" catch-all) and every disposition being one of the
  five umbrella-defined categories, not open-ended.
