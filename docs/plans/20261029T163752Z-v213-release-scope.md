# v2.13.0 release scope

## Intent and authority boundary

Prepare the smallest coherent release after independently verified v2.12.0.
The proposed version is **v2.13.0** because the primary work adds a bounded,
adopter-facing governance permission. The other two slices provide measurement
evidence and safer release inputs; they are not presented as equal product
headlines.

This plan chooses scope and sequence only after Gate 1 approval. It does not
approve any implementation beyond the three already-governed child plans, and
it does not authorize a version edit, tag, package, Release, deployment or
publication. Those actions require a later freeze reconciliation and separate
release-publication plan.

Release baseline: annotated tag `v2.12.0`, peeled commit
`e045d20b073ce31341cd0d460469fac60cdbab5a`, published and independently
verified 2026-10-28.

## IN scope

### 1. Bounded record-only publication termination

Implement approved plan
`20261027T045944Z-record-only-publication-termination` first. The adopter-facing
result is a narrowly conjunctive exception that terminates recursive approval
only for publication of exhausted, objectively pre-authorized coordination
records or cited post-action evidence. Existing ordinary Human review remains
valid.

Acceptance is the approved four-file scope, all seven eligibility conditions,
every exclusion, strict projection validation, exact-head review and normal
Human Gate 2. The implementation MR is a rule change and cannot use the new
exception to merge itself.

Compatibility: additive but authority-sensitive. This item is the semantic
version driver and the release headline.

### 2. Distribution-scan profiling and baseline evidence

After MR !3066's approved plan metadata is on `main`, implement
`20260920T083259Z-distribution-scan-profiling-slice-b` exactly as approved by
decision `20261029T162805Z-governor-reviewer-dn8m`.

Acceptance is feature-gated counters and `agov dist diagnose`, the deterministic
runtime-generated tracked/untracked/hidden/in-root-symlink fixture, default-build
absence of the diagnostic command, and a reproducible baseline report covering
fixture and real-tree repeated fresh-process runs with explicitly uncontrolled
filesystem caches, per governor amendment
`20261029T194912Z-governor-reviewer-nskj`. Controlled cold/warm comparison remains
deferred. The report must state what the measurement does not prove and support
no cache-effect, speedup, optimization, CI-critical-path or pristine-checkout claim.

The revised scope acknowledges `20261029T192922Z-release-publisher-api-amendment`,
which also owns this plan file. This amendment changes only profiling acceptance
in section 2; the publisher worker retains section 3's CI-item wording. Preserve
both independent deltas when reconciling the shared file. The acknowledgment
coordinates edits, without requiring either completed approval to wait on itself.

Compatibility: no default runtime behavior or schema change. This is a
measurement and evidence slice, not a speedup claim. The root changelog records
the landed foundry/tooling work; the adopter changelog must not imply that the
default release binary gains the feature-gated diagnostic command.

### 3. CI reproducibility pins as a release prerequisite

After MR !3340's approved plan metadata is on `main`, implement
`20261028T194451Z-ci-reproducibility-pins` exactly as approved by decision
`20261029T162807Z-governor-reviewer-kmp6`.

Acceptance requires the approved create-only publisher amendment
`20261029T192922Z-release-publisher-api-amendment`: the verified official
Alpine tag and linux/amd64 digest, tokenless and mountless base/runtime tool
checks, current-scanner Trivy evidence, one create-only Releases API POST with
the bounded tag/non-overwrite checks, and its credential-containment and fake-
transport tests. The declared Rust version, versioned and checksummed rustup
installer, and advisory-only drift checks with their negative tests remain
required. Any unresolved HIGH or CRITICAL image finding stops for a governor
risk decision. Rollback never restores `latest` or the obsolete publisher.

Compatibility: foundry CI only. This work makes the release path safer but is
not an adopter-facing AGF feature. The root changelog records it when merged;
the adopter changelog must not imply that adopter CI becomes reproducible.

## Sequence and parallelism

1. Publish and merge the two Gate 1 decision records, then merge the metadata-
   only approval updates to plan MRs !3066 and !3340.
2. Begin the record-only publication implementation from current `main`.
3. After their plan merges, the profiling and CI-pin implementations may run in
   parallel because their affected paths are disjoint. Each needs its own claim,
   branch, implementation MR, tests, exact-head review and Gate 2.
4. Freeze only after all three implementations are merged and re-observed
   together on current `main`.

The release does not wait for any excluded item. If an IN item cannot satisfy
its own approved acceptance criteria, the governor must explicitly amend this
plan; it is never silently dropped or weakened.

## Explicit exclusions

- Any optimization arising from issue #137 or the profiling report, including
  caching or a `git ls-files` membership substitute.
- Any decision or behavior change for outside-resolving symlinks.
- Native builder-image work.
- Issue #133 watcher/work-exhaustion state changes.
- Issue #138 instruction-delivery changes after its inconclusive Phase A.
- Issue #141 philosophical-lenses self-application documentation.
- CurlClient response-size protection, `main.rs` modularization and MkDocs
  dependency locking.
- Pinning the Alpine packages installed inside `release:create`; this remains
  disclosed residual risk and must have a durable record before release.
- Any blocking promotion of the advisory CI-pin drift check.
- Any backlog item admitted only by age, label, milestone or visibility.

## Freeze and release acceptance

Before a release-publication child plan is drafted:

1. all three IN implementations have exact-head Gate 2 decisions, are merged
   to `main`, and are re-observed together on that current `main` head;
2. the full Rust workspace and shipped distribution suites pass on the chosen
   freeze candidate;
3. the documentation-estate steward completes the release-content-freeze
   sweep, including rule/template/site projection parity;
4. both changelogs account for every post-v2.12 merged change without turning
   internal CI or measurement work into adopter claims;
5. the CI-pin residual-risk record exists and every vulnerability finding has
   a fix or explicit governor disposition;
6. version/provenance/docs manifests are still unchanged at this stage; and
7. a separate publication plan names the exact freeze SHA and owns version
   edits, protected tag, pipelines, packages, OCI image, GitLab Release and
   anonymous verification.

## Evidence status and downstream impact

The record-publication exception is **Empirically informed** by foundry's
observed recursive decision-publication chain; it is not claimed as broadly
validated across adopters. The profiling work produces measurement evidence
without pre-judging its result. The CI-pin work is preventive foundry
operations. Capability and evidence labels must remain separate in release
notes.

## Validation and review

- `agov plan validate` passes.
- The blocking changed-plan collision check reports no unacknowledged overlap.
- An independent contribution audit confirms the IN/EXCLUDE boundary, version
  rationale, and changelog treatment.
- Gate 1 approval names the exact reviewed plan head.

## Risks and rollback

- **Scope inflation:** controls are the three enumerated IN items and explicit
  exclusions; amendments return through reviewed Gate 1.
- **Internal work advertised as product:** controls are separate compatibility
  statements and changelog ownership.
- **Authority-sensitive rule misunderstood as general self-merge:** controls are
  the approved conjunction, exclusions, examples and independent Gate 2 review.
- **Release delay from evidence work:** no excluded follow-up can become a
  release blocker without an explicit plan amendment.

Before freeze, rollback is to amend or supersede this plan by governor decision.
After publication, corrections use a new governed release; tags and published
artifacts are never rewritten.
