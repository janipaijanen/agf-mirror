# Plan: v2.4.5 — next unplanned release, content assessment

## Trigger

Governor asked to plan the next release that doesn't yet have a plan. v2.4.3
is being cut now (MR !533). v2.4.4 is already claimed by MR !490's
stable-SHA procedural trial (Gate 1 draft, blocked on MR !459's rebase) —
that number is spoken for even though it isn't executed yet. This plan
covers **v2.4.5**, the next genuinely unplanned slot, and assesses what
content is ready or likely to be ready for it.

## Release objective

v2.4.5 is a **documentation credibility and release-hygiene patch**. It has
two required outcomes:

1. remove the already-observed historical-version coupling from public status
   banners; and
2. produce an auditable, current-state critical review of the published v2.4.3
   documentation using a shared protocol across multiple LLM perspectives,
   followed only by bounded remediations that clear their own gates.

The release does not claim that every available LLM reviewed the documentation,
that model agreement is empirical validation, or that historical reviews were
performed against the v2.4.3 snapshot.

### Required review-evidence workstream

The historical evidence names Lumo, Claude Code, Grok, ChatGPT, GitHub
Copilot, Cursor, OpenAI Web, Codex, and GPT-5.6 Sol High across different
snapshots and scopes. That is useful provenance, but it does **not** establish
that all of those systems critically reviewed the current implementation.

Before v2.4.5 is cut, create a separate Gate 1 plan for a standardized review
run with this frozen protocol:

- **Baseline:** the immutable published v2.4.3 tag/commit and its public docs
  URL. If v2.4.3 is not published successfully, this workstream cannot start.
- **Target:** evaluator-facing and adopter-facing documentation, including the
  homepage, adoption decision path, installation/first-change path, roles and
  gates, evidence/maturity vocabulary, tooling reference, exit path, and AI
  evaluation dossier.
- **Shared review packet:** the same page list, target-audience statement,
  questions, severity vocabulary, and required evidence fields for every
  reviewer. Reviewers may not see another model's findings before submitting
  their independent first pass.
- **Minimum panel:** Claude and Codex/GPT-5.6 Sol High plus at least two
  externally supplied independent model perspectives selected from Gemini,
  Grok, Cursor, GitHub Copilot, Lumo, or another named system. Record the exact
  model identifier when the provider exposes it; otherwise record the product,
  date, interface, and the identifier limitation. Do not list a model as a
  reviewer unless its output is actually captured.
- **Per-review provenance:** reviewer/product, exact model identifier or stated
  limitation, UTC date, reviewed SHA/tag and URL, complete prompt/protocol,
  unedited response, and normalized findings with evidence references.
- **Synthesis:** deduplicate findings without converting vote count into truth;
  separate factual defects, usability judgments, roadmap proposals, and claims
  requiring human or empirical evidence.
- **Advisory checks:** fact-checker verifies factual findings; academic-peer-
  reviewer checks evidence-strength and independence wording; contribution-
  auditor reviews the package and proposed dispositions.

The review package may ship in v2.4.5 only after that sub-plan receives Gate 1
and its exact artifacts receive Gate 2. Any resulting product-documentation
change needs an exact-text fact-check and Gate 2. Findings that change schemas,
roles, validators, authority, CI enforcement, or adopter contracts are routed
to v2.5.0 rather than smuggled into this patch.

## Proposed sequencing

1. v2.4.3 completes its exact-SHA Gate 2, merge, tag, and publication path.
   Freeze that published tag/commit as the multi-LLM review baseline.
2. MR !537 (status-banner decoupling) clears contribution-auditor review
   and governor Gate 2, merges to `main`.
3. Draft and approve the separate standardized-review Gate 1 plan, execute the
   independent reviews, preserve provenance, fact-check the findings, obtain
   academic-peer and contribution-auditor dispositions, and merge the final
   evidence package after exact-SHA Gate 2.
4. Plan and implement only the bounded documentation remediations accepted from
   that synthesis. Each remediation must merge before the release cut; an open
   finding or unapproved proposal is not release content.
5. If #30/MR !463 clears its integration-evidence gap (refresh onto current
   `main`, re-run scoped evidence, fresh Gate 2) before step 7, it merges
   too. If not, it rolls to a later release — not blocking.
6. If MR !485's implementation (agent YAML + `MANIFEST.yaml` entry) is
   drafted, reviewed, and clears Gate 2 before step 7, it merges too.
   Otherwise it rolls forward, since Gate 1 approval alone doesn't obligate
   inclusion in a specific release.
7. Per `release-via-merge-request-rule.md`: cut `release-2.4.5` from `main`
   containing the required outcomes and whichever conditional items have
   merged by then, bump `VERSION` and
   `CHANGELOG.md`/`agf/CHANGELOG.md` on the release branch only, open the
   release MR, and merge after Gate 2 review of that exact SHA.
8. Tag `v2.4.5` and push immediately after the release MR merges, per the
   rule's no-further-confirmation step.

## Explicit exclusions

- This plan does not implement, merge, or tag anything itself.
- This plan does not reopen any already-approved Gate 1 or Gate 2 decision.
- This plan does not obligate MR !485's implementation or #30's fix to land
  in v2.4.5 — both are conditional on clearing their own review state before
  the branch is cut, matching the pattern already established for v2.4.3.
- This plan does not authorize contacting external model providers, purchasing
  access, or presenting unavailable model reviews as complete. Human-supplied
  outputs may be incorporated only with the provenance fields above.
- This plan does not predetermine the review findings or authorize their
  remediation before the review sub-plan and applicable gates are complete.
