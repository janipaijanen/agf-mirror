# Plan: AGF v2.4.3 — documentation-quality and information-architecture backlog

## Origin and scope boundary

v2.4.2 (`docs/plans/v2.4.2-public-experience-and-evidence-presentation.md`)
explicitly froze its own scope and excluded, without re-verifying, the 11
WARN/INFO items carried forward from the post-release audit
`20260721T212235Z-planner-architect-qj7s`. Per that plan's own words: "any
of them entering scope requires a plan amendment and new Gate 1 ... that
re-verifies its live status first." This plan is that re-verification and
Gate 1 submission, done as a **separate** release rather than folded into
v2.4.2, so v2.4.2's own patch stays a clean, narrowly-scoped yes/no for its
reviewers.

This plan does **not** cover issue #53 (CI/build-latency measurement,
explicitly deferred by `sgp8`/`8neq`) or the `seq` field deprecation
decision flagged open in `deprecation-policy-rule.md`. Both are different
risk/effort classes than a documentation-quality patch and are left for
their own separately-scoped work.

## Frozen scope — the entire v2.4.3 content scope, no more

1. Hardcoded version-pin literals — **reframed per h3q6.** This item does
   not claim to fix drift detection; it does not. The concrete, honest
   benefit is editor discoverability: a comment at each of the 6 sites
   naming `agf/VERSION` as the single canonical value, so that whoever
   performs the next version bump has a grep target
   (`grep -rn "agov:2\.4\.1"`) that surfaces all 6 occurrences instead of
   however many they happen to remember. No claim is made that this
   prevents a future release from missing one — a release-time validator
   is the only mechanism that could make that claim, and it is explicitly
   out of scope (see non-goals). If a validator is wanted, it is a
   separate tooling plan, not folded in here.
2. Misdirected metadata link — both occurrences (`docs/index.md:113`,
   `roles-and-gates.md:35`) repointed to the canonical slug.
3. Off-palette `#CCCCCC` in `governance-loop.dot` and
   `adoption-exit-flow.dot` — replaced with a palette-compliant color;
   grey-semantic-overload cross-checked against `agf/docs/visual/
   palette.md` and resolved or explicitly accepted with reasoning
   recorded.
4. Level-2 naming inconsistency — **direction reversed per h3q6.**
   "Surface-defined" is canonical (it is what `evaluate.md`,
   `ai-evaluation-dossier.md`, `maturity-vocabulary.md`, and `README.md`
   already say, consistently, today). The correction targets the single
   outlier: `.claude/rules/docs/implementation-honesty-rule.md`'s three
   "Schema-defined" occurrences (lines 29, 36, 66) are changed to
   "Surface-defined" to match. No public-facing evaluator page changes
   its Level-2 name under this item — see the progressive-disclosure
   section below for why this does not trigger that standard.
   `maturity-vocabulary.md` remains the single source of truth other
   pages reference.
5. `bgcolor=white` tension — **direction chosen, per h3q6, not left
   open.** Documented as an accepted, intentional light-background
   assumption, in `agf/docs/visual/palette.md` only — no `.dot` source
   file is edited under this item. `palette.md`'s existing "Light and
   dark backgrounds" design-constraint bullet already states fills work
   on white/light-cream and dark-mode variants are not yet defined; this
   item extends that same bullet to state explicitly that the diagram
   canvas background (`bgcolor=white`, not just fill tokens) is the same
   accepted assumption, and names the exact 7 files from item 5 of the
   re-verification section above as the sources it covers.
   `coordination-map-example.dot` (hex `#ffffff`) is explicitly out of
   scope for this item, per the re-verification section's reasoning. No
   figure source is made background-agnostic under this plan.
6. `<figure>`/`<figcaption>` semantics and non-title alt text — added to
   exactly one file: `agf/docs/site/reference/figures.md`, the canonical
   reference page that already embeds all 7 figures named in item 5 with
   caption and source-line context. The per-page embeds of the same
   figures elsewhere (`day-to-day.md`, `roles-and-gates.md`,
   `downstream-impact.md`, `evidence-and-learnings.md`,
   `first-governed-change.md`, `exit-and-decommission.md`,
   `review-and-release.md`) are **not** touched by this item — a sitewide
   pass is a non-goal, not a stretch goal (see non-goals below; the
   "stretch goal" framing is removed per h3q6's correction).

**Nothing else is in scope.** The open CLI-onboarding-pointer question
above requires an explicit decision to enter scope; it is not implicitly
included. Issue #53 and the `seq` deprecation decision are out of scope
per "Origin and scope boundary" above.

## Non-goals

- No sitewide `<figure>`/`<figcaption>` retrofit — only
  `agf/docs/site/reference/figures.md`, named exactly in frozen-scope item
  6 above. The per-page embeds elsewhere are not touched by this plan.
- No new release-time validator implementation for version-pin drift —
  this plan documents the single source of truth for an editor's benefit
  only; it does not claim to detect drift. Building an automated check is
  separately-scoped future work if wanted.
- No background-agnostic rework of any figure source — the `bgcolor=white`
  tension is resolved as an accepted, documented assumption (frozen-scope
  item 5), not by removing the assumption.
- No macOS/darwin build target (see "Explicitly out of scope" above).
- No CI-latency work (#53) and no `seq` deprecation decision.
- No change to any schema, role definition, tool/CLI surface, or
  adopter-facing contract.

## Implementation MR structure

One implementation MR, six named commits (one per frozen-scope item
above), each independently reviewable:

1. Version-pin single-source-of-truth note (6 sites, discoverability
   framing only — see reframed item 1).
2. Metadata-link fix (2 files).
3. Off-palette color fix + grey-overload resolution (2 figure sources).
4. Level-2 naming canonicalization — `implementation-honesty-rule.md`
   only (3 occurrences changed to "Surface-defined"); no public-doc file
   changes.
5. `bgcolor=white` tension resolution — `agf/docs/visual/palette.md`
   only, documenting the accepted light-background assumption; the 7
   named `.dot` sources are unchanged.
6. `<figure>`/`<figcaption>` + non-title alt-text pass on
   `agf/docs/site/reference/figures.md` only (7 embeds).

Stop condition per commit: if fact-checker review (before Gate 2) finds a
factual defect in any commit's text that isn't a wording-level fix, that
commit is reverted and re-planned rather than patched under review
pressure — same discipline as v2.4.2's implementation MR structure.

Release packaging (`release/v2.4.3` branch, VERSION bump, CHANGELOG)
remains a later step after this MR passes Gate 2, per
`release-via-merge-request-rule` — no direct commits to `main`, no
tagging before merge, no `release/v2.4.3` branch before this plan is
Gate 1 approved.

## Patch-version justification

Every item in the frozen scope corrects a documentation/figure-quality
defect (stale link, off-palette color, naming drift, accessibility gap,
unresolved tension) on already-shipped public surfaces. None add a new
schema field, role, tool, CLI flag, MCP surface, or adopter-facing
contract — same character as v2.4.2, justifying **patch** version
treatment.
