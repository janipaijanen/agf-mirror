# Plan: AGF v2.4.3 — documentation-quality and information-architecture backlog

## Origin and scope boundary

v2.4.2 (`docs/plans/v2.4.2-public-experience-and-evidence-presentation.md`)
explicitly froze its own scope and excluded, without re-verifying, the 11
WARN/INFO items carried forward from the post-release audit
`20260721T212235Z-planner-architect-qj7s`. Per that plan's own words: "any
of them entering scope requires a plan amendment and new Gate 1 ... that
re-verifies its live status first." This plan is that re-verification and
Gate 1 submission, done as a **separate** release rather than folded into
v2.4.2, so v2.4.2's own patch stays a clean, narrowly-scoped yes/no for its
reviewers.

This plan does **not** cover issue #53 (CI/build-latency measurement,
explicitly deferred by `sgp8`/`8neq`) or the `seq` field deprecation
decision flagged open in `deprecation-policy-rule.md`. Both are different
risk/effort classes than a documentation-quality patch and are left for
their own separately-scoped work.

## Frozen scope — the entire v2.4.3 content scope, no more

1. Hardcoded version-pin literals — **reframed per h3q6.** This item does

   performs the next version bump has a grep target
   (`grep -rn "agov:2\.4\.1"`) that surfaces all 6 occurrences instead of

   prevents a future release from missing one — a release-time validator
   is the only mechanism that could make that claim, and it is explicitly

   re-verification section's correction above. Exact token named now, per

   time. Category corrected per `nhtr`'s `V243-LEARN-OWNER-R4` — see
   below.** `#CCCCCC`/`grey-light` stays exactly as-is (it is the
   canonical palette token); only `governance-loop.dot`'s `learn` node
   changes. Reading the DOT source directly: `learn` currently renders as
   `style="filled,dashed", fillcolor="#CCCCCC", color="#888888",
   fontcolor="#1A1A1A"` — the "Reference / deferred content" treatment,
   which is wrong because writing a learning record is an active,
   current pipeline step, not deferred or reference material.

   The prior revision assigned `learn` to "AI action," reasoning that
   this project's `learning` skill is AI-executed. `nhtr`'s `V243-LEARN-
   OWNER-R4` correctly rejects that: AGF does not reserve learning

   records are authored by whichever party — human or AI — identifies
   the finding; no single-actor category in the four "who acts
   exclusively" rows (Human decision / AI action / Automated check /
   Reference-deferred) honestly fits.

   defines a fifth row for exactly this shape: **Shared concept** — fill
   white (no fill), border `blue-mid` `#0077BB`, text `blue-mid`

   category: it is neither AI-exclusive, human-exclusive, an automated
   validated outcome, nor deferred reference content — it is a concept
   whose responsibility is genuinely shared between human and AI actors,
   which is exactly `learn`'s situation. **Exact change:** `learn` is

   fontcolor="#0077BB"` (drop `dashed` and the grey fill/border; the
   node keeps its existing plain box shape, so no `shape=` change is

   fontcolor="#0077BB"]`, inserted into the existing invisible-edge
   ordering chain (`sk_oval -> sk_diamond -> sk_ai -> sk_automated ->
   sk_reference -> sk_shared`, or wherever keeps the key's rank order
   sensible) so the legend documents every category the figure actually
   uses. The `sk_ai` label reverts to its original `"AI action\n(plan /
   implement)"` — `learn` no longer belongs to that row, so no legend
