# Code of Conduct

## Our commitment

This project is a governance framework -- it exists to help teams build
better software with AI agents. We welcome contributions from anyone who
shares that goal, regardless of background or experience level.

## Expected behaviour

- **Be constructive.** Critique ideas and evidence, not people.
- **Back claims with evidence.** This framework changes based on field
  evidence, not opinions. "My project found X" is more useful than
  "I think X."
- **Respect anonymization.** Never reveal another adopter's real project
  or organisation name, even if you know it. Codenames exist for a reason.
- **Be honest about what works and what doesn't.** Overkill findings are
  as valuable as gap findings. The framework improves from both.
- **Keep discussions focused.** Issues and merge requests should stay on
  topic. Tangential ideas deserve their own issue.

## Unacceptable behaviour

- Personal attacks, insults, or derogatory language
- Deliberately revealing anonymized project identities
- Submitting fabricated evidence or learnings
- Spam, off-topic promotion, or unsolicited commercial pitches
- Harassment in any form

## Scope

This code of conduct applies to all project spaces: issues, merge
requests, discussions, and any communication channel associated with
the project.

## Enforcement

Instances of unacceptable behaviour may be reported to the project
maintainer (see LEARNINGS.md for contact). All reports will be reviewed
and responded to appropriately. The maintainer is obligated to maintain
confidentiality with regard to the reporter.

## Attribution

This code of conduct is adapted for the specific needs of an
evidence-driven governance framework. It prioritizes constructive
technical discourse and adopter privacy.
